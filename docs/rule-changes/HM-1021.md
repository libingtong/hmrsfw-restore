### 2. 为什么不靠「固定页面时钟」解决

- 门槛和基线**已经**在固定时钟：`tools/gate/replay.mjs` 从 HM-4 起就有 `page.clock.setSystemTime(<HAR 录制那一分钟的开头>)`，时钟随后正常走。快速通道 `tools/fast-lane/replay/guard.mjs` 的 `setFixedTime` 只用于 POC 30 页的离线回归（`verify-confirm.mjs`、`verify.mjs`），不在录制和门槛路径上。所以 HM-1021 描述里「基线和门槛没有固定时钟」不准确。实际情况是时钟只对齐到分钟，没有冻结。
- 改成 `setFixedTime`（冻结 `Date`、计时器照走）有两个问题。第一，去不掉 TinyMCE 的 id，因为里面有 `Math.random()`。第二，会改变页面行为：lodash `debounce` 等按 `Date.now()` 计时的代码，在冻结的时钟下 `timeSinceLastCall` 恒为 0，`timerExpired` 会无限重排，回调永远不触发。这会影响全部页面，所有基线都要重录。`clock.install`、`pauseAt` 会接管全部计时器，问题更大。
- 倒计时弹窗不是原因：`招聘公告提示` 弹窗只在 `t.user.isShowGG` 为真时渲染（同文件 `:13951` 附近，初值 `isShowGG:!1` 在 `:2344`）。这份 HAR 下两次运行都没出现弹窗，`overlay` 两次相同，都为空。`setInterval` 只改 `L.value` 并 `console.log`，不动 DOM。所以不需要 `clock.install`，也不需要在交互脚本里等倒计时结束。

### 3. 规则

**tinymce-generated-id**（`kind: html`）：把 `\b(tiny-vue|aria)_\d{15,}` 替换成 `$1_#`。生成的 id 至少有 15 位数字：随机数至少 1 位，计数至少 1 位，毫秒时间戳 13 位。前缀、后缀（`_ifr`）、属性名、元素，以及同一占位被谁引用，照常比较。短 id（如 `aria_12`）和其他前缀不受影响。同类先例：`46-echarts-instance-id`（HM-652）。

**replay-clock-now**（`kind: now`，`windowMinutes: 15`）：处理精确到秒的日期时间，形如 `YYYY-MM-DD HH:mm:ss`，分隔符可以是 `-` 或 `/`，日期和时间之间可以是空格或 `T`。按页面时区换算，时刻落在 [时钟起点, 起点 + 15 分钟) 内的，替换成 `⟦now ####-##-## ##:##:##⟧`：只去掉数字，分隔符和精度保留。

- 时钟起点和时区偏移由 `runPage` 记进 `run.clock`，取值是 `setSystemTime` 用的那一刻，时区偏移在页面里用 `getTimezoneOffset` 读。`compareRuns` 对两侧都用基线第一次运行的 `clock`，`unstableKeys` 用 run A 的。两侧回放的是同一份 HAR，起点相同。
- 旧基线没有 `clock`，两侧都不替换，行为与现在相同。所以已通过的页面不受影响，只有重录或刷新过的基线才用上这条规则。
- 窗口外照常比较：起点之前的时刻，包括 HAR 里录制前的数据时间、昨天、几天前；超过 15 分钟的；格式不同的，如 `HH:mm` 对 `HH:mm:ss`、`-` 对 `/`；UTC 墙钟。
- 15 分钟远大于一次运行的时长：加载最多等 30 s，步骤每步约 1–6 s。负载 35 时整份基线跑了 203 s。

### 4. 为什么不算放宽

两条规则都只把原版自己每次运行都会变的值换成占位，判据和阈值不变。

- id 的数字由随机数和时间戳组成，页面代码决定的只有前缀、在哪个元素上、被谁引用，这些都还在比。
- 「现在」的秒数取决于这次回放从导航到挂载花了多久。页面代码决定的是打不打印当前时间、用什么格式、打印在哪里，这些都还在比。还原版如果把当前时间打印成别的格式、打印在别处，或者漏打，仍然失败。还原版如果打印的是 HAR 数据里的时间，那个时刻早于时钟起点，不会被替换，仍然逐字比较。
- 没有这两条，`unstable` 会把整个 `<input>` 标签和 TinyMCE 的若干标签变成通配：现有 `compareRuns` 的「易变掩码」按标签切分，差一处就整个标签不比。有了这两条，这些标签的其余属性都能逐字比较。比对比原来更严，不是更宽。

### 6. 顺带：`Unexpected token '<'`

原版自带，不是 HAR 没对上。

- `Editor.1751615607545.js:923471` 起，`kr="/"`，`language_url: kr+"tinymce/langs/zh_CN.js"`、`skin_url: kr+"tinymce/skins/ui/oxide"`。插件 `lists link media table wordcount fullscreen` 从 TinyMCE 的 baseURL 加载 `plugins/<名>/plugin.min.js`。
- `legacy-dist/usercenter` 没有 `tinymce/` 目录，回放服务器对未知路径回落到 `index.html`。浏览器把 HTML 当脚本执行，报 `Unexpected token '<'`：语言包 1 次，插件 6 次，共 7 次（基线 `errors`）。
- 录制员是在测试环境上录的，不是离线回放，也报了 6 次（`$RESTORE_STATE/record/page.uc.addNewsDetails/result.json` 的 warnings）。说明测试环境对这些路径同样返回 HTML，原版线上就是这样：编辑器界面是英文，插件没有加载。
- 还原版 `hmrsfw-vue/apps/uc/public` 也没有 `tinymce/`，两侧行为一致，不需要处理。`errors` 不在比对项里。
