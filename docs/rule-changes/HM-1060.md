## HM-1060：`legacy-dist/usercenter` 缺原版部署的 `/tinymce/` 资源，原版基线的编辑器变成英文、没有皮肤

### 1. 变更

- `legacy-dist(usercenter): tinymce runtime assets`：新增 `legacy-dist/usercenter/tinymce/langs/zh_CN.js` 和 `legacy-dist/usercenter/tinymce/skins/ui/oxide/`（13 个文件），内容逐字节取自原版部署（测试环境 `hamiusercentertest.rencaidanao.com` 的同名路径，匿名 GET 静态文件，没有登录）。
- 不改门槛脚本、比对规则、阈值和公共库清单。`plugins/` 不补：原版部署本身就没有，见第 3 节。

这不是比对器的规范化，属于第十五节第 2 条第 5 项「测试资产问题」：基线回放用的归档缺了原版部署里本来就有的静态文件。`legacy-dist` 是门槛的比对基准，不能直接改 `main`，所以走规则变更单复核。

### 2. 现象

- `page.uc.addNewsDetails`（HM-480）门槛的 text/html 差异：原版编辑器菜单、工具栏是英文（Edit / View / Format、`title="Bold"`…），还原版是中文。
- 门槛已经把 `@/shared/Editor.vue` 换成原 chunk（`shimmed`），两侧编辑器代码相同，差异只来自 `/tinymce/` 静态资源。
- `baseline.json` 两次运行各有 7 条 `Unexpected token '<'`：语言包 1 条、插件 6 条。`tools/gate/serve.mjs`、`tools/record-lib.mjs` 对归档里没有的路径回落到 `index.html`。

### 3. 证据

| 位置 | 内容 |
| --- | --- |
| `legacy-dist/usercenter/assets/Editor.1751615607545.js:923587` | `kr="/"`，`language_url:kr+"tinymce/langs/zh_CN.js"`、`language:"zh_CN"`、`skin_url:kr+"tinymce/skins/ui/oxide"`、`content_css:kr+"tinymce/skins/ui/oxide/content.min.css"`：原代码要中文界面和 oxide 皮肤 |
| 测试环境 `/tinymce/langs/zh_CN.js` | 200 `application/x-javascript`，17397 字节，SHA-256 `04ec622189c51beb…17db6bb`，387 条 |
| 测试环境 `/tinymce/skins/ui/oxide/*`（13 个文件） | 全部 200，`text/css` / 字体；与 `tinymce@5.10.3` npm 包（即 `hmrsfw-vue/apps/uc/public/tinymce/skins/ui/oxide/`）逐字节一致 |
| 测试环境 `/tinymce/plugins/lists/plugin.min.js`、`plugin.js` | 200 `text/html`，1231 字节，与不存在路径 `/nonexistent-xyz.js` 的回落页相同：原版部署确实没有插件 |

结论：原版线上编辑器是中文界面、有皮肤、6 个插件加载失败。现有基线是英文、无皮肤，比原版线上少了语言包和皮肤，不是原版行为。

HM-1021 第 6 节写的「原版线上就是这样：编辑器界面是英文」不对：那次「录制员在测试环境上录」的页面同样由 `legacy-dist` 提供静态文件（`tools/record-lib.mjs`），只有接口走测试环境，所以也拿不到 `/tinymce/`。同一节说还原版 `apps/uc/public` 没有 `tinymce/` 也已过时（E7 收尾时已加入）。

### 4. 还原版一侧（同时处理）

`hmrsfw-vue` 的 `apps/uc/public/tinymce/langs/zh_CN.js` 原来取自 `tinymce-i18n@22.2.11`（460 条），和原版部署的 387 条不同（如原版不翻译 `Line height`，新版译成「行高」）。公共库升级单 HM-1060 在分支 `restore/upg-19-a1`（`d3db69f`）把它换成原版部署的同一文件。皮肤两侧本来就相同，不动。

### 5. 影响

- 只有依赖 `Editor.1751615607545.js` 的页面加载 `/tinymce/`，目前只有 `page.uc.addNewsDetails`。其他页面的回放不会请求这些路径。
- `self-check.mjs` 的复制检测只用工单自己的 chunk 和 CSS（`legacy-dist/<site>/assets/` 下）当原包，不包括 `tinymce/`，不影响任何工单。
- 手动对整个 `legacy-dist` 运行 `tools/check-copied.mjs <hmrsfw-vue>/apps` 时，`apps/uc/public/tinymce/**` 会报整份文件相同。这些是 TinyMCE 的第三方运行时资源，原版部署和还原版本来就是同一份，属于 `copy-exemptions.json` 里 `apps/portal/public/third/*` 同类的「另行裁定」，需要时另开规则变更单登记，本单不改豁免表。
- 比对更严，不是更宽：编辑器的界面文字、`title`、`aria-label` 改为和原版线上的真实文案逐字比较。

### 6. 合入后

1. 裁定员运行 `node tools/tick.mjs rerecord page.uc.addNewsDetails`，用新归档重录并重算基线（同时补上 HM-1021 要求的 `clock`；当前基线 `createdAt` 2026-10-21T14:43Z，早于 HM-1021 合并，`basic_time` 的秒级时间戳差异也由此消除）。
2. 全量回归由合并自动触发；已通过页面不加载 `/tinymce/`，预期无变化。
