### 1. 现象

HM-273（`page.portal.xjhm.home.advertTop`）修好图标以后，final 已经通过，load 只剩一处差异，差异目录 `$RESTORE_STATE/gate/page.portal.xjhm.home.advertTop-a1`，还原版 commit `c85352b`：

```
原版（两次一样）：data-index="0" aria-hidden="true"  class="slick-slide"                           opacity: 0
                  data-index="1" aria-hidden="false" class="slick-slide slick-active slick-current" opacity: 1
还原版：          data-index="0" aria-hidden="false" class="slick-slide slick-active slick-current" opacity: 1
                  data-index="1" aria-hidden="true"  class="slick-slide"                           opacity: 0
```

两边的页面代码相同：原 chunk `advertTop.17833206362006.js` 里是 `autoplay:!0,autoplayspeed:"4000",…,beforeChange:ft,effect:"fade"`，还原版 `advertTop.vue` 的 `<a-carousel>` 属性逐项一致。差别在于快照落在哪个时刻：

| | settleMs |
| --- | --- |
| 原版基线 run 1 / run 2（`baseline/page.portal.xjhm.home.advertTop/baseline.json`） | -1（30 秒内没等到稳定）/ 26614 |
| 还原版（gate.1 的两次运行） | 4347 / 2526 |

原版是通过父页面 `xjhm.home.index` 录制的（recordVia），整个首页和外壳一起加载，要几十秒才稳定；还原版只挂载本页，2–4 秒就稳定，赶在第一次翻页（3050 ms）之前。所以同一份代码，原版快照停在第 N 张，N 取决于用了多久，还原版总停在第 0 张。原版两次运行的 final 就停在不同的 slide（基线 `unstable: ["final.html"]`），说明这是时间态；这次 load 两次碰巧都停在第 1 张，没有被通配掩码盖住。

### 2. 原因：轮播库的自动播放是按挂载时刻计时的

门户和用户中心的轮播都是 ant-design-vue 的 `a-carousel`，底层是 vc-slick。原包内置的代码与还原版 npm 包（门户 `ant-design-vue-portal` 3.2.15、用户中心 `ant-design-vue` 3.2.20，`es/vc-slick/inner-slider.js`）一致：

| 内容 | 门户 `index.1783320636200.js` 偏移 | 用户中心 `index.1751615607545.js` 偏移 |
| --- | --- | --- |
| `pauseOnHover` 默认 `true` | 549598 | 1620751 |
| `handleAutoPlay`：`"update"` 时若已是 `hovered` / `focused` / `paused` 就不重启 | 574009 | 1645162 |
| `this.autoplayTimer=setInterval(this.play,this.autoplaySpeed+50)` | 574195 | 1645348 |
| `onTrackOver:function(){this.autoplay&&this.pause("hovered")}`（`pause` 先 `clearInterval`） | 574769 | 1645922 |
| 轨道 `onMouseover: pauseOnHover ? this.onTrackOver : …` | 575872 | 1647025 |

### 3. 改动

`runPage` 给两边都加一个初始化脚本 `pauseCarousels(200)`：每 200 ms 对页面上每个 `.slick-track` 派发一个**不冒泡**的 `mouseover`。这走的是库自己的「鼠标悬停暂停」路径：`onTrackOver` → `pause("hovered")`，清掉计时器，库里后续的 `"update"` 重启也会跳过已暂停的轮播。效果是两边的轮播都停在初始 slide，不再取决于页面多久才稳定。

- **为什么不算放宽**：比较的内容一项没少。slide 的个数、顺序、内容、克隆，`slick-active` / `aria-hidden` / `opacity`，初始 slide，轨道样式，都照常逐字比较。改变的只是快照前两边处在同一个状态，原来是各自停在随机时刻的状态。原来靠通配掩码通过的轮播页，基线变稳定后掩码没了，比较变严；原来只因停的 slide 不同而失败的页，同样的代码现在相同。
- **没有副作用**：事件不冒泡，只有轨道自己的监听器收到；页面在轮播外层写的 hover 处理不会运行，测试里断言了计数为 0。没有开 autoplay 的轮播，`onTrackOver` 直接返回，测试里断言渲染结果与不加脚本时逐字相同。
- **交互步骤**：真实指针经过轮播再离开时，库会恢复自动播放（`onTrackLeave` → `handleAutoPlay("leave")`）。下一次 200 ms 派发会再次暂停，这远小于最短的翻页间隔（autoplaySpeed + 50）。测试里断言了指针离开后仍停在第 0 张。
- **覆盖不到的**：`pauseOnHover: false` 的轮播仍然照常播放，与改动前相同；swiper 等其他轮播库不在此列。
- **代价**：「自动播放会不会转」从此不在回放里比较。它本来就没有被可靠地比较过（取决于快照时刻）；`autoplay` 属性本身由静态 self-check 的渲染等价检查比对。

### 4. 旧基线

旧基线是在轮播播放中录的，与新回放不可比。`baselineFor` 对没有 `carouselPaused` 标记、且任何一次运行的 load / final 根候选里含 `slick-track` 的基线，返回 `refresh`。门槛会用基线自己的 HAR 离线重跑 `baseline.mjs`，不访问测试环境，与 HM-253 / HM-342 / HM-380 的处理相同。现有 `$RESTORE_STATE/baseline/` 下 224 份基线中有 17 份会重算：`Guidance.GuidanceHome.index`、`cityHome.index`、`personnelAssessment.index`、`region.skill.index`、`resumeAnalysisReport.postCompetitivenessAnalysis`、`sjz.enterpriserecruitment.enterpriserecruitment`、`talents.cityHome.index`、`talents.index.advertTop`、`talents.index.index`、`talents.index.jobRecommend`、`talents.index.review`、`talents.index.talentRecommend`、`xjhm.bigData.statistics`、`xjhm.home.advertTop`、`xjhm.home.index`、`zcyz.bigData.components.pieRader`（以上为门户）、`uc.sceneFairSign`。没有开 autoplay 的轮播，重算结果不变。
