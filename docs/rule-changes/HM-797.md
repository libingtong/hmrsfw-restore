## HM-797：门槛把 `target=_blank` 新标签页的请求计入被测页的交互请求序列（启动快慢竞态）

- 分支：`rule/hm-797-page-owned-requests`（基于 `main` `c12aad7`），每条规则一个提交：
  1. `rule(replay): page-owned-requests`：`tools/gate/replay.mjs` 的 `runPage` / `openedTarget`，`tools/gate/har.mjs` 的 `routeApi`（把请求对象交给记录回调），`tools/gate/compare.mjs` 的 `project` / `hint`，`tools/baseline.mjs` 存 `opened`，`tools/gate.mjs` 报告里多两项诊断；用例 `tools/test/gate-page-scope.test.mjs`；
  2. 本文。
- 合入 `main` 后，第 1 个提交 cherry-pick 到工具仓库 `restore/fast-lane`，分支 `rule/hm-797-fast-lane`，做法同 HM-779。
- 提出：裁定员；复核：两个非 Anthropic 家族的复核员。
- 来源：HM-248（`page.portal.recruitMarket.marketHome.home`）`steps.requests` 失败；HM-245（`page.portal.recruitMarket.marketDetail.index`）疑似同因，已核实不是，见第 4 节。
- 不动的东西：归一化规则（`rules/compare/`）、像素阈值、请求集合和请求序列判据、HAR、公共库清单、交互脚本、`SITES.*.origSel`。

### 1. 问题：别的页面的请求被记成被测页面的请求

**新标签页是怎么来的。** HM-248 的交互脚本第 3 步是 `{"click":"查看更多"}`。`step()` 取最后一个可见匹配，也就是「热门职位」的「查看更多」：

| 文件:偏移 | 内容 |
| --- | --- |
| `legacy-dist/portal/assets/home.17833206362002.js:17447` | `JobList?isJobMarket=1",target:"_blank"},{default:…" 查看更多 "…` |
| 还原版 `apps/portal/src/views/recruitMarket/marketHome/home.vue:372` | 同一个链接，`target="_blank"` |

点击之后，**新标签页**打开 `/JobList?isJobMarket=1`，被测页面本身不发请求。

**改动前门槛怎么记。** `routeApi` 挂在浏览器 context 上（`tools/gate/har.mjs`），context 里所有页面的 `/xf-api/` 请求都进同一个 `log`。`runPage` 把 `phase !== "load"` 的都当成被测页面的交互请求（`res.stepLog`）。新标签页从启动到发请求要一段时间，它的请求有没有赶在采集前（最后一步的等待加上 `waitQuiet`，约 2 秒）发出，取决于它启动得多快：

- 原版是静态包，启动慢。HM-248 的两次基线运行 `stepLog` 都是空的。
- 还原版是按需编译，启动快。新标签页的外壳请求按 shell 集合扣掉以后，还剩 JobList 自己的 `GET …/xfSysAreainfo/getInfo`、`POST …/findJobListForWebRedis`，报告是「request #1 after load: original (none), restored step3 …（0/2 requests）」。

**原版自己也有竞态。** 第 4 节重跑 HM-248 的原版时，第 1 次有 10 个新标签页请求落在第 3 步之前，第 2 次一个都没有：被扣掉的是外壳请求，所以结果没变，但这说明落不落进来全看时机。下面 4 页的基线两次运行都把新标签页的请求记成了本页的请求，而且记在哪一步也随时机变化：基线记在 step3，重跑时落在 step1。

### 2. 改动

只改测量范围：

- **请求归属**：`routeApi` 把 Playwright 的请求对象交给记录回调。`runPage` 用 `request.frame().page()` 判断请求来自哪个页面。被测页面的主框架和 iframe 发的请求照旧进 `log`。被测页面打开的其他页面发的请求进 `res.otherRequests`，只用于诊断，不参与比较，也不影响稳定判断里的 `lastRequestAt`。没有 frame 的请求（service worker）无法归属，照旧算被测页面的。
- **打开页面作为步骤事件**：被测页面每打开一个页面，就记一条 `{phase, target}`，加载阶段记在 `res.load.opened`，交互阶段记在 `res.opened`。
  - `target` 取新页面第一个导航请求的 URL。这个请求发出时页面还不存在，Playwright 拿不到它的 frame。之所以用它，是因为页面本身可能停在错误页：回放不出网，测试环境域名会被中止，`page.url()` 是 `chrome-error://chromewebdata/`。
  - 回放源下的地址记 `路径?参数#hash`：去掉 `_t`，其余参数排序。两侧本地端口不同，只比路径。外部地址记 `host + 路径`，不带参数，例如 `autoLogin` 的参数里可能有登录信息。
  - 新页面照旧运行，不关闭，交互本身不变。
- **比对**：`project` 多两项 `load.opened`、`steps.opened`，按顺序比 `"<phase> <target>"`，判据和 `steps.requests` 一样，两次原版运行任一次相同即可。失败提示只写阶段和路径，不写参数值。改动前录的基线没有这两项，**按「没打开任何页面」处理**，不跳过。
- `baseline.mjs` 把 `opened` 存进 `baseline.json`，也写进 `seq.json`。`gate.mjs` 的 `report.json` 多 `restOpened`（不带参数）和 `restOtherRequests`，只用于诊断。

### 3. 为什么不算放宽

- **比的还是被测页面的全部请求。** 被测页面自己发的请求（包括 iframe）一条不少，判据、顺序、请求体 SHA-256 都不变。移出去的只是另一个页面的请求，那些请求本来就不是被测页面发的：同一段代码在原版和还原版里打开的是同一个页面，那个页面另有自己的工单和门槛。
- **多比了一项，比原来严。**
  - 原来点开新标签页后，比的是一场竞态的结果：新标签页慢就什么都不比，快就比另一个页面的请求。
  - 现在两侧都必须在**同一步**打开**同一路径**的页面，顺序也要一致。少打开、多打开、目标不同，都会失败（用例第 2 项）。
  - 改动前录的基线没有 `opened`，按「没打开任何页面」比，所以还原版多打开一个页面也会失败，不会因为基线是旧的就放过（用例第 3 项）。
- **不改交互和数据。** 交互脚本、HAR、等待时间、归一化规则、像素阈值都没动，新标签页也不关闭。

- **这 9 页的基线在合并时重录**，用本分支的 `baseline.mjs`，在 `mergeRule` 开回归之前换进去。
  - 原因：旧基线没有 `opened`，按新规则算「没打开页面」。其中 4 页（表中标「有」的）的 `stepLog` 里还混着新标签页的请求。不重录的话，还原版只要和原版一样打开页面就会失败。

### 5. 验证

- **复现**（不提交的一次性脚本）：同一个夹具站点，被测页面带一个 `target=_blank` 链接，新标签页一侧 4 秒后发请求，另一侧立刻发。
  - `main`：`steps.requests` 失败，提示「request #1 after load: original (none), restored step0 POST /jobList (0/2 requests)」，和 HM-248 的失败形式相同；
  - 本分支：没有失败项。
- **用例** `tools/test/gate-page-scope.test.mjs`，真浏览器，4 项：
  1. 新标签页一侧慢一侧快，两个方向比都没有失败项。用例先断言快的一侧新标签页的请求确实在采集前发出了，记在 `otherRequests` 里，竞态是真实存在的；被测页面自己的请求（含 iframe）两侧都在；
  2. 被测页面自己的请求不同，`steps.requests` 失败；打开的目标不同，`steps.opened` 失败，href 不同也会让 html 失败；不再打开新页面，`steps.opened` 失败；
  3. 旧基线没有 `opened`：还原版打开了页面，`steps.opened` 失败；没打开，就没有失败项；请求照常比较；
  4. 新页面的导航被中止（外部域名）时，记录的是打开时的目标，不是 `chromewebdata`。

  4 项在 `main` 的代码上全部失败，在本分支上全部通过。
- **全集**（不含 scheduler、concurrency）：126/126 通过。`node tools/gate/har.mjs --selftest` 通过。
- **全量回归**：合入后由 `mergeRule` 开 `rule-regression`。
  - 已通过页面的原版都没有打开页面，`stepLog` 也没有另一个页面的请求，所以原版一侧的投影不变。
  - 还原版一侧只有在打开了页面时结果才会变，变化是：新页面的请求不再计入；原版没打开而还原版打开了，改报 `steps.opened` 失败。后者是真实差异。
