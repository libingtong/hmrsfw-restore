- 分支：`rule/hm-251-record-via-root`（基于 `main` `fa317fc`），每条规则一个提交：

  2. 本文。

- 提出：裁定员；复核：两个非 Anthropic 家族的复核员。
- 来源：HM-251（`page.portal.talents.index.review`）回执与两轮修正员结论；HM-253（`talents.index.jobFair`）、HM-256（`talents.newPark.industry`）同因。

### 1. 问题

工单工具把「只被别的页面当组件引用」的页面（`queue/*.json` 里带 `recordVia` 的 50 张，全部是门户）用引用它的页面的路由录制（`docs/work-orders.md` 第 74 行）。门槛对这些页面没有任何特殊处理：

- **原版侧**：`baseline.mjs` 回放父页面 `/talents/index`，按 `SITES.portal.origSel = "main > *"` 取根，得到的是布局头部 `headerBox`、父页面根 `bgColor`、`bg-f padT50`、`setPos` 等和布局底部，**review 组件本身不是候选**，它在 `bgColor` 里面好几层。
- **还原侧**：`gate.mjs` 把 `wo.target`（`review.vue`）直接挂成 `/talents/index` 路由，`#poc-main > *` 取到的是 review 的根 `marT20`。review 单独挂载，**没有父页面传入的 `codeList`**。

结果（`gate.1`，规则 `8ada37b35e61`，提交 `ca4dc51`）：

| `steps.requests`、`load.overlay` | 同上：请求体不同（HAR 里找不到），toast 不同 |

### 2. 改动（只对带 `recordVia` 的页面生效）

- **选根**：两侧都取「组件自己的根」：带组件 scopeId 的最外层元素，选择器 `[sid]:not([sid] *)`（`common.mjs` `scopeRootSel`）。scoped 组件模板里的每个元素都带它的 scopeId，组件根同时带父组件的；子组件根带本组件的，但在本组件根里面，被 `:not([sid] *)` 排除。多根组件（Fragment）取到每个顶层元素，组件用了多次时按文档顺序都是候选，比的是与还原版第一个根 class 相同的第一个（沿用 HM-779 的 `pickCandidate`）。
  - 原版 scopeId：工单 `components[].scopeId`（chunk 只有一个组件时取它，多个时取与目标文件同名的那个；50 张都有 scopeId）。
  - 还原版 scopeId：`@vitejs/plugin-vue` 编译出的 `_export_sfc(_sfc_main, [["__scopeId","data-v-…"]])`，由 `scopeIdPlugin` 在编译时按文件记下，按需编译和完整构建都适用。还原版没有 `<style scoped>` 时报 `root` 失败，不改比别的元素。
- **挂载**：还原侧路由挂父页面工单的还原文件（`recordVia` 指向的工单的 `target`），预编译也包含它；父页面在这条分支上还没有还原文件时报 `build` 失败并写明父工单。这样组件拿到父页面传入的 props，和原版一样。
- **扣除父页面的部分**：原版的 shell 探针本来就把**本页 chunk** 换成空组件再跑一遍（`baseline.mjs`），得到的请求和 toast 正是「父页面和其他兄弟组件」的。请求本来就在两侧一起扣除（`loadSet`、`stepSeq`）；toast 原来只扣原版侧，因为还原侧单独挂载时没有外壳。现在还原侧也有父页面，所以对 recordVia 页面 toast 也在还原侧按同一份清单扣（`compareRuns` 的 `inParent`），按多重集扣，组件自己多出来的 toast 照样比较。
- **基线迁移**：`baseline.json` 新记 `sel`（录制时用的选择器）。门槛发现 HAR 和交互脚本都没变、只有选择器变了时，用同一份 HAR 离线重跑 `baseline.mjs`（只回放 `legacy-dist`，不访问测试环境），dry-run 写到自己的目录，不覆盖共享基线。现有 45 份 recordVia 基线在各自下一次门槛时重算一次，每页约 2.5 分钟。录制员以后录的基线直接用新选择器。

### 3. 为什么不算放宽

- **比的内容和判据不变，只是对齐比对对象和比对条件。** 原来原版比的是父页面整页的某个元素（或布局头部），还原版比的是单独挂载、缺 props 的组件，比较本身没有意义；现在两侧比的都是「父页面里的这个组件」。html、text、overlay、请求集合与序列、像素、已知差异，判据和阈值一个没动。
- **扣除的是父页面的东西，组件自己的一样不少。** 扣除清单来自原版 shell 探针（把本页 chunk 换成空组件），两侧用同一份；组件自己发的请求（`queryLatestQuestionsList`、`queryQuestionsList`）不在清单里，照样要求相同（用例第 4 项：组件请求缺失仍失败、组件多出的 toast 仍失败）。
- **找不到就失败。** 原版或还原版取不到组件根时报 `root`，父页面没有还原文件时报 `build`，都不通过，不回落到别的元素。
- **非 recordVia 页面完全不变。** `origSelOf` 对它们返回原来的 `origSel`，基线里没有 `sel` 时按 `origSel` 处理，不会重算；还原侧仍是 `REST_SEL`、挂自己的文件；`inParent` 为假。`scopeIdPlugin` 只读编译结果、不改输出。

### 4. 验证

- **原版侧**：对 review 用同一份 HAR 跑新的 `baseline.mjs`（输出到临时目录），两次运行的 load、final 根都是 `marT20`，`unstable` 为空，交互请求 `step0`、`step2` 都是 `queryQuestionsList`，与原基线的 `stepLog` 一致。
- **门槛 dry-run**（工具分支 + hmrsfw-vue `restore/fast-lane` `ca4dc51`，`--dry-run --from build`；本机没有门槛员的加密密钥，用占位值，结果只用来看比对对象）：
  | 失败项 | 改动前（`gate.1`） | 改动后 |
  | --- | --- | --- |
  | `load.root` / `final.root` | 失败 | 通过（两侧都是 `marT20`） |
  | `load.requests` / `steps.requests` | 失败 | 通过 |
  | `load.overlay` | 失败 | 通过 |
  | `load.text` / `final.text` | 未比（无根） | 通过 |
  | `load.html` / `final.html` | 未比（无根） | 失败：只差一处 `img` 的 `src`（原版 `/assets/moreInfo.1783320636200.png`，还原 `/assets/shared/moreInfo.png`），替换后逐字相同 |
  | `pixel` | — | 失败 28.8%：还原侧帮助中心背景图、波浪图和两张图片没加载 |

  剩下的两项是真实差异（资源地址和背景图），属于还原或门槛资源处理（同 HM-778 一类），不是选根问题，本单不处理，交回修正流程。
- **测试**：新增 `tools/test/record-via-root.test.mjs`，4 项：
  1. `origSelOf`：普通页面仍是 `origSel`；recordVia 页面是组件的 scope 根；多组件 chunk 取与目标文件同名的组件；没有 scopeId 时报错；
  2. 在 Chromium 里：布局头部、父页面根、组件（两个实例，其中嵌套一个子组件）、只属于父页面的元素，选择器只取到组件的两个根；多根组件取到每个顶层元素；
  3. `scopeIdPlugin` 只从 SFC 主模块取 scopeId，不从 `?vue&type=style` 子请求和非 `.vue` 文件取；
  4. `compareRuns` 的 `inParent`：父页面的 toast 和请求两侧都扣；不加 `inParent`（普通页面）时还原侧 toast 照常比较；组件自己多出的 toast、缺少的请求仍失败。

  `tools/test/` 全部 150 项：148 通过；`gate-assets.test.mjs` 的 2 项（按需编译资源地址，需 `HMRSFW_APP_DIR`）在 `main` `fa317fc` 上用同一份 hmrsfw-vue 检出同样失败，与本改动无关。
- **全量回归**：合入后由 `mergeRule` 开 `rule-regression`。已通过的页面里没有 recordVia 页面（它们按第 1 节的原因都过不了），其余页面比对方式不变，结果应逐字相同。
