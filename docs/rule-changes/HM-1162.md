## HM-1162：用户中心布局外的顶级路由，还原侧也取 `#app > *`

- 分支：`hm-1162/uc-bare-route-rest-root`（基于 `main` `1aea841`），每条规则一个提交：
  1. `rule(gate): uc-bare-route-rest-root`：`tools/gate/common.mjs` 新增 `restSelOf(wo)`，`tools/gate.mjs` 用它代替固定的 `REST_SEL`；`docs/gate.md` 补一句；用例在 `tools/test/record-via-root.test.mjs`；
  2. `rule(compare): poc-main-hook`：`rules/compare/53-poc-main-hook.json` + `tools/gate/rules.mjs` 的 `pocMainHook`；用例 `tools/test/compare-rules-poc-main-hook.test.mjs`；
  3. 本文。
- 提出：裁定员；复核：两个非 Anthropic 家族的复核员（`tick.mjs open-rule-review`）。
- 来源：HM-1162（`page.uc.403`）。3 次尝试、3 轮修正，门槛 7 次都报同样 3 条：
  - `root load`：`no original root candidate with class null`；
  - `root final`：`no original root candidate with class "contentmain"`（原版候选 `"ant-layout"`）；
  - `render load`：`restored page root (#poc-main > *) is empty`。
  - 第 2、3 次回执都写了同一条 needsFromSkeleton：/403 不经过 Home.vue，还原侧没有 `#poc-main`。
- 不动的东西：

  - 像素阈值；
  - 请求集合和请求序列判据；
  - HAR、基线（`baseline.json` 的 `sel` 仍是 `#app > *`，`origSelOf` 不变，不会触发重算）；
  - 公共库清单和 hmrsfw-vue 公共库；
  - `SITES.*.origSel`、`bareRoutes`、`bareSel`；
  - 布局内页面、门户页面、recordVia 页面的取根方式（仍分别为 `REST_SEL` 和 scope 根）；
  - 候选选取（HM-779 `pickCandidate`）。

### 1. 问题：HM-1225 只改了原版侧，还原侧的前提不成立

HM-1225 让 4 条布局外顶级路由（`/previewresume`、`/login`、`/403`、`/autoLogin`）在原版侧取 `#app > *`。它第 2 节写的是“还原侧不变：还原应用没有外壳，所有页面本来就挂在 `#poc-main` 下”。对用户中心来说，这个前提已经不成立：

| 位置（hmrsfw-vue `integration`） | 内容 |
| --- | --- |
| `apps/uc/src/router.ts` 第 92 行起 | 路由表 `routes`：`path:"/"` 是布局路由（`component: Layout`），全部业务页面是它的 `children` |
| `apps/uc/src/router.ts:256`–`259` | `/previewresume`、`/login`、`/403`、`/autoLogin` 是和 `"/"` 同级的顶级路由，与原表 `Fht` 相同 |
| `apps/uc/src/legacy/components/App.vue` 模板 | `<a-config-provider><RouterView/></a-config-provider>`，没有 `#poc-main` |
| `apps/uc/src/legacy/components/Home.vue:71` | `#poc-main` 只在布局里，就是原版 `.overscoll > div` 那一层（注释写明是回放比对钩子） |
| 工具仓库 `tools/gate/appserver.mjs` `gateRouteCode` | 兜底路由只在 `router.resolve(recordPath)` 解析不到时才加；/403 能解析，所以不加，页面不会被挂到 `#poc-main` 下 |

所以还原版 /403 的 DOM 是 `#app > (a-config-provider 不产生元素) > div.error-page`，和原版一样。门槛却在还原侧固定取 `#poc-main > *`：
- 加载时 `#poc-main` 不存在，结果为空。于是报 `render load`；还原侧加载根的 class 为 null，又报 `root load`。
- 交互「返回首页」进入 `/main` 后，还原侧取到布局里的 `div.contentmain`，原版侧取到 `#app > *` 即 `section.ant-layout`。两边不是同一层，于是报 `root final`。

不管页面怎么写都过不了：3 次尝试、两个家族（DeepSeek、Sonnet）写出的页面都与原 chunk 一致（self-check 通过），结果都一样。

### 2. 改动

**规则 1 `uc-bare-route-rest-root`（`tools/gate/common.mjs` `restSelOf`）**

- `recordPath` 的路径（去掉 query 和 hash）在该站 `bareRoutes` 里时，还原侧返回 `bareSel`（`#app > *`）。其他情况返回 `REST_SEL`。
- recordVia 页面仍按 scope 根取（`gate.mjs` 先判断 `restSid`，顺序不变）。
- 只有用户中心配置了 `bareRoutes`，门户不受影响。
- 用例保证每条 bare 路由两侧选择器相同：`restSelOf(wo) === origSelOf(wo)`。

**规则 2 `poc-main-hook`（tree 规则）**

- 只去掉值恰好为 `poc-main` 的 `id` 属性，其他 id、这个元素的其他属性和子树都照常比较。
- 规则 1 生效后，/403 交互后两侧的 final 根都是整个布局 `section.ant-layout`，比对范围里第一次包含了门槛自己加的钩子：
  - 原版（`legacy-dist/usercenter/assets/index.1751615607545.js:123:379706`，布局组件 `__name:"home"`，`123:378303`）：`st("div",null,[…KeepAlive…])`，这层 div 没有属性；
  - 还原版（`Home.vue:71`）：`<div id="poc-main">`。
- `legacy-dist` 里没有 `poc-main`。它是门槛的定位钩子，不是页面内容，去掉后两侧是同一种写法。
- 门户的 `<main id="poc-main">` 不会落进比对的根（门户 origSel 是 `main > *`，钩子在根的外面），所以规则 2 对门户不起作用。

### 3. 为什么不算放宽

- **判据不变，只是两侧取同一个位置。** 原版侧取根的位置已由 HM-1225 复核通过。本单只让还原侧取 DOM 里同一层：两边都是 `#app` 的第一层子元素。html、text、overlay、请求集合与序列、像素、已知差异，判据和阈值一个都没动。
- **找不到仍然失败。** 还原页面没挂载时 `#app > *` 为空，照样报 `render`；类名对不上照样报 `root`。
- **范围是封闭的。** 只对 `bareRoutes` 的 4 条生效。这份清单有用例对照原路由表（HM-1225），本单新增的用例对照还原路由表：4 条都必须是 `router.ts` 里的顶级记录，`App.vue` 里也不能有 `poc-main`。只要还原侧改成把它们放进布局，或给 App 套上 `#poc-main`，用例就会失败，不会悄悄取错层。
- **规则 2 只去掉一个固定的属性值。** 这是门槛自己加的钩子，原包里没有。元素在不在、位置、data-v、style、子树，照常比较。

### 4. 验证

**离线核对还原版 DOM**

做法：
- hmrsfw-vue `restore/page.uc.403-a3`（`569a046`），用门槛的 `startOnDemand` 起服务；
- Playwright 拦截全部接口，统一回空，`config.json` 和 `getSettingValueByCode` 回非敏感占位值，没有请求离开 127.0.0.1；
- localStorage 只放一个占位 `userCenterInfo`，让守卫放行。

结果：

| 阶段 | `#poc-main > *`（现状） | `#app > *`（本改动） | 原版基线（`sel = #app > *`） |
| --- | --- | --- | --- |
| 加载 `/403` | 空 | `div.error-page` | `error-page` |
| 点「返回首页」后 `/main` | `div.contentmain` | `section.ant-layout` | `ant-layout` |

- 交互后，还原版 `#poc-main` 的属性是 `data-v-a0429b24`、`id`，父元素是 `.overscoll`。原版基线同一位置是 `.overscoll > div[data-v-34be80b2]`，没有 id。两边只差规则 2 去掉的那个属性（data-v 由 `scope-id` 规则处理）。
- 本机没有 `RESTORE_ASSETS`（裁定员不拿 HAR），所以没有做 HAR 回放的门槛全量比对。合入后由门槛员 regate 本单出结果。

**测试**
- `HMRSFW_APP_DIR=<hmrsfw-vue> node --test tools/test/record-via-root.test.mjs tools/test/compare-rules-poc-main-hook.test.mjs`：10/10 通过。新增 2 + 2 项：
  - `restSelOf`：bare 路由返回 `#app > *` 且等于 `origSelOf`；`/404`、`/myresume`、门户返回 `REST_SEL`；
  - 还原路由表核对：4 条 bare 路由都是顶级记录，`App.vue` 里没有 `poc-main`；
  - `poc-main-hook`：只去掉 `id="poc-main"`；`id="poc-main2"`、其他 id、同一元素的其他属性、子树差异都照常报出。
- `tools/test/compare-*.test.mjs`、`gate-page-scope`、`gate-route`、`gate-auth`：51 项里 50 项通过。唯一失败的是 `gate-auth` 的「queue orders with a role read the site's login state」，`main` `1aea841` 不带本改动时同样失败（HM-1225 第 4 节已记录），和本改动无关。
