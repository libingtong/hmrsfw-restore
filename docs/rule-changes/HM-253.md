### 1. 问题

门槛 `gate.1`（`$RESTORE_STATE/gate/page.portal.talents.index.jobFair-a1/`）里，HTML、文本、请求、浮层全部通过，只有像素差。

把基线 `shot.png` 和门槛 `rest.png` 逐像素比（阈值 0）：

| 对比 | 不同像素 | 范围 (x0,y0)–(x1,y1) | x < 1860 的不同像素 |
| --- | --- | --- | --- |
| 原版 vs 还原版 `rest.png` | 1.405% | (1862,127)–(1919,378) | 0 |
| 原版 vs 还原版 `rest.retry.png` | 1.405% | 同上 | 0 |
| 原版第 1 次 vs 原版第 2 次 `shot.r2.png` | 0.843% | (1862,124)–(1919,291) | 0 |
| 还原版两次之间 | 0 | — | — |

门槛报的 0.663% 是带容差的结果。可以看出，差异全部落在截图最右边 58 列的一条里，组件本身的像素逐个相同。

这一条画的是「点击展开」侧栏。它不在本组件里，是父页面另一个组件 `homeRight` 的：

| 文件:偏移 | 内容 |
| --- | --- |
| `legacy-dist/portal/assets/homeRight.1783320636200.js:12087` | `A("div",{class:"rightFixed",onClick:q},[…"点击展开"…])` |
| `legacy-dist/portal/assets/homeRight.1783320636200.js:13123` | scopeId `data-v-85da16f2`，不是本页的 `data-v-bb4a8a3f` |
| `legacy-dist/portal/assets/homeRight.1783320636200.css:3070` | `.rightFixed[data-v-85da16f2]{position:fixed;top:540px;right:0;width:51px;height:148px;…}` |
| `legacy-dist/portal/assets/homeRight.1783320636200.css:3332` | `animation:gelatine-85da16f2 2.5s infinite` |
| `legacy-dist/portal/assets/index.178332063620098.js:1067`、`:527` | 父页面 `talents/index` 同时引入 `homeRight` 和 `jobFair` |
| `legacy-dist/portal/assets/jobFair.1783320636200.js`、`.css` | 没有 `rightFixed`，也没有任何 `position:fixed` |

为什么两边的位置不同：

- 侧栏固定在视口 `top:540px`。它落进组件截图的哪一行，取决于组件在视口里的位置。
- 原版有布局外壳 homeView，它的头部占位 `.headerBox{height:90px}`（`legacy-dist/portal/assets/homeView.1783320636200.css:516`）。门槛的还原版不挂外壳（HM-250、HM-779）。所以还原版的组件在页面里高 90px。
- 组件高 526px，整个落在视口内，截图不滚动。于是侧栏在原版截图里从第 148 行开始，在还原版截图里从第 238 行开始，正好差 90 行（取的是第 1905 列颜色跳变的行号）。
- 侧栏本身还在无限循环播放 gelatine 动画，所以原版自己两次截图也在这一条上差 0.843%。

结论：这 0.663% 来自父页面兄弟组件的固定元素和外壳的高度，与 jobFair 无关，页面代码无法修到通过。HM-262 处理过同一类问题（外壳的固定头部画进页面根），但它明确不覆盖 recordVia 页：这类页的根带父页面的 scopeId，候选上找不到本页 scopeId，就照旧截图。

### 2. 改动

**offscope-fixed**（截图时的测量范围）：

- 只对 recordVia 页生效，两侧做法相同：
  - `baseline.mjs` 传入工单组件的 scopeId（`pageScopeId(wo)`）；
  - `gate.mjs` 传入还原文件编译出的 scopeId（HM-251 的 `restSid`）；
  - 其他页面不传这个参数，截图方式不变。
- `captureRoot` 截每个组件根之前，把满足以下全部条件的元素标记出来，设为 `visibility:hidden`，截完马上撤掉样式和标记：
  - 计算样式是 `position: fixed` 或 `sticky`；
  - 不在组件根里面；
  - 不是组件根的祖先；
  - 自己不带组件 scopeId，里面也没有带组件 scopeId 的元素（组件 teleport 出去的内容）。
- 不变的东西：
  - 只改可见性，布局不变；
  - DOM 树、innerText、浮层、请求都在隐藏之前取，内容和以前完全相同；
  - 组件自己的固定元素照常截入（用例第 1 项）。
- scopeId 只认 `data-v-` 加十六进制，校验通过才拼进选择器。
- **旧基线自动重算**：基线里新记一个 `offscopeFixed: true`。recordVia 工单的基线没有这个标记时，`baselineFor` 走 HM-251 已有的 `refresh` 路径，用原 HAR 离线重算一次（约 2.5 分钟），不用人工重录。

### 3. 为什么不算放宽

- **像素阈值没变，比的仍是组件根的整张截图。** 拿掉的只是组件外面的固定元素画在组件上的部分：
  - 它属于父页面的兄弟组件（侧栏）或外壳；
  - 这些另有自己的工单（`page.portal.talents.index.index` 是 HM-329）。
- **两侧同样处理。** 原来相同的部分处理后仍然相同。被隐藏元素下面露出来的是组件自己的像素，两边如果不同，照样报出来。
- **不是减少覆盖。**
  - 组件自己的固定元素和 teleport 内容照常比较。
  - 隐藏只在截图那一刻生效。
  - 能否隐藏，看的是 DOM 上组件根的包含关系和 scopeId，不看位置或时机。
- **这是 HM-251 的延续。** HM-251 把 recordVia 页的比较对象从「父页面」收窄到「组件自己的根」，但截图仍会带进组件外面的固定元素。本规则补齐了这一点。

### 4. 影响面

- `queue/` 里有 recordVia 工单 50 张（分属 18 个父页面），现有基线 45 份。
- 合入后，每份 recordVia 基线在下一次门槛（或回归）时会自动离线重算，然后按新做法比较。
- 非 recordVia 页面的基线和比较完全不受影响：不传 `componentScope` 就什么都不标记（用例第 2 项）。
- 已通过的 recordVia 页，只有在被隐藏元素下面组件自己的像素两侧不同时才会翻为失败；这种情况是真差异，不是规则造成的。两侧去掉同一类元素后，原来相同的像素仍然相同。
- 已知受益：本页（HM-253）。父页面 `talents/index` 下还有 7 个子组件（jobRecommend、advertTop、infoRecommend、review、homeList、talentRecommend、frendLinks），截图凡是与 `top:540px` 那一条相交的，都会带上同一个侧栏。

### 5. 验证

- `node --test tools/test/gate-offscope-fixed.test.mjs`，连同 `gate-shell-shots`、`record-via-root`、`gate-advance`、`gate-report`、`compare-*`、`gate-known-diffs`、`coverage`，46 项全部通过；`rule/hm-253-fast-lane` 上同一组用例也全部通过。
- `gate-offscope-fixed` 用真实 Chromium 做了 3 项：
  1. 隐藏范围：组件外的 fixed 侧栏和 sticky 导航被隐藏；组件根、组件自己的 fixed 元素、祖先、静态兄弟、teleport 内容都可见；截完 DOM 上不留标记；
  2. 没有 scopeId 或 scopeId 非法时，什么都不标记；
  3. 同一个组件，上方有或没有 90px 外壳头部：不加规则时两张截图不同；加规则后逐字节相同，并且与「根本没有侧栏」的截图逐字节相同。
- 本页的真实重放（原版重算基线、还原版过门槛）要用 `$RESTORE_ASSETS` 下的 HAR。按 `docs/pipeline.md` 第 101 行，只有门槛员和录制员能读，裁定员没有做。合入后由 HM-253 的 `--regate` 完成，第 1 节的逐像素结果是这次实测的依据。
