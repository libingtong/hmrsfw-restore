### 3. 为什么是等价写法，不算放宽（原证据，未变）

算法和证据与 HM-902 完全相同（本提交是该提交的逐字节 cherry-pick），复述关键论证：原正则是 `^` + 转义后的 `S0` + `[\s\S]*?` + `S1` + … + `Sk` + `$`，不带标志；`maskSegments`/`maskTest` 判断还原版 `r` 是否以 `S0` 开头、以 `Sk` 结尾、中间按顺序包含 `S1…S(k-1)`（每段取最左出现位置，段之间不重叠）。两种写法接受的字符串集合相同（`test(r)` 为真 ⟺ `r` 能切成 `S0 · 任意 · S1 · … · 任意 · Sk`），用 3000 组随机文本/HTML 和 204 份基线 + 172 份门槛报告全量对照过，0 处不同（HM-902 原文档，见本提交历史 `a35a262`）。本次新增的证据只是：这次重现的地图页（HM-1153/eMap）再一次落在「旧写法会抛错、新写法给出正常结论」的那一类，和原文档列出的 6 页（含 `talents.index.advertTop` 等）同属一类问题。
