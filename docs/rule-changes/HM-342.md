### 1. 问题

基线 `shot.png` 和门槛 `rest.png`（`$RESTORE_STATE/gate/page.portal.talents.index.frendLinks-a1/`）两张都是 1200×110。逐行逐像素比（阈值 0）：

| 行 | 不同像素 | 原版 | 还原版 |
| --- | --- | --- | --- |
| 0–108 | 0 | — | — |
| 109（最后一行） | 1200（整行） | `71,71,71` | `241,243,244` |

1200 / (1200×110) = 0.909%，就是门槛报的数。组件自己的像素逐个相同，差异只在最后一行。

这一行不是组件画的。原 chunk 里的证据：

| 文件:偏移 | 内容 |
| --- | --- |
| `legacy-dist/portal/assets/frendLinks.17833206362002.js:2788` | 组件根 `{class:"marB70 marT40"}`，scopeId `data-v-0b7f2f66`（`:2754`） |
| `legacy-dist/portal/assets/*.css` | 搜不到 `.marB70`：这个外边距在原包里不存在，根的下边缘没有留白 |
| `legacy-dist/portal/assets/index.178332063620098.js:5348` | 父页面 `talents/index` 的最后一个 `bgColor`（`q`，`:3813`）里，依次是 `main padT30`（review）、`main`（本组件 `yt`）。本组件是父页面流内内容的最后一块 |
| `legacy-dist/portal/assets/homeView.1783320636200.js:6160` | 外壳 homeView 在 `RouterView` 之后渲染 `{class:"footCls flex"}` |
| `legacy-dist/portal/assets/homeView.1783320636200.css:2386` | `.footCls[data-v-48a64537]{…;height:240px;background:rgba(51,51,51,.9);…}`：画在白底上是 `71,71,71` |

还原版一侧，门槛不挂 homeView（HM-250、HM-779），父页面直接挂在 App 下。紧挨在下面的是 App 自己的底部：

- `hmrsfw-vue` `apps/portal/src/legacy/components/App.vue:85`：`<footer>`；
- `apps/portal/src/legacy/components/Foot3.vue:61`：`.fotBox{background:#F1F3F4}`，就是 `241,243,244`。

为什么会截进去：

- 组件根是透明的，高度带小数。离线重放测得的值见第 5 节：原版根顶 `y=560.5`，底 `669.09375`，高 `108.59375`。
- Playwright 的元素截图取的是框的外接整像素矩形：顶向下取整、底向上取整，所以是 560–669 共 110 行。
- Chromium 绘制时，框边按四舍五入对齐到整像素：`bgColor` 的底边 669.09 画到 669 为止。所以第 669 行（截图第 109 行）整行都是根下面那个元素画的。
- 原版那里是外壳的 `footCls`，还原版那里是 App 的 `fotBox`。两个都是外壳，也都不属于本组件。

HM-253 已经处理过同一类问题：组件外的 fixed、sticky 元素画进组件截图，那次只隐藏了这两类。HM-262 只对页面级根生效（recordVia 根上没有本页 scopeId）。所以普通流内的邻居仍会从边缘行渗进来。页面代码无法修到通过：加边距或改高度都会偏离原代码。

### 2. 改动

**offscope-all**（截图时的测量范围，只对 recordVia 页生效，两侧做法相同）：

- 原来 `markOffscopeFixed` 只标记组件外的 fixed、sticky 元素。改名为 `markOffscope` 后，标记组件外的**所有**元素，也就是满足以下全部条件的元素：
  - 不在组件根里面；
  - 不是组件根的祖先；
  - 自己不带组件 scopeId，里面也没有带组件 scopeId 的元素。这样组件 teleport 出去的内容、组件的其他根和其他实例都保留。
- 只标记最外层的那个元素（父元素已经标记的就跳过）。`OFFSCOPE_CSS`（`[attr],[attr] *{visibility:hidden!important}`）会盖住它里面的内容。截完马上撤掉样式和标记，这一点和以前一样。
- 截图里剩下的是组件本身，加上它下面祖先元素的背景。
- 其他做法都和 HM-253 相同：
  - 只改可见性，布局不变；
  - DOM 树、innerText、浮层、请求都在隐藏之前取，内容和以前完全相同；
  - scopeId 只认 `data-v-` 加十六进制，校验通过才拼进选择器；
  - 原版一侧 `baseline.mjs` 传工单组件的 scopeId，还原版一侧 `gate.mjs` 传还原文件编译出来的 scopeId。
- **旧基线自动重算**：基线新记 `offscopeAll: true`。recordVia 工单的基线没有这个标记时，`baselineFor` 走 HM-251 已有的 `refresh` 路径，用原 HAR 离线重算一次，不用人工重录。
  - 新基线同时保留 `offscopeFixed: true`，因为 `main` 和 `restore/fast-lane` 共用 `$RESTORE_STATE/baseline`。fast-lane 在 cherry-pick 之前读到新基线，也不会再触发一次 HM-253 重算。

### 3. 为什么不算放宽

- **像素阈值没变，比的仍是组件根的整张截图**，尺寸也不变（本页仍是 1200×110）。拿掉的只是组件外面的元素画进截图的部分。这些元素是父页面的其他块和外壳（`page.portal.talents.index.index`、`page.portal.talents.homeView`），各有自己的工单。
- **两侧同样处理。** 被隐藏元素下面露出来的，是组件自己的像素和它的祖先背景。两边如果不同，照样报出来（用例 `gate-offscope-edge` 第 3 项：组件内部改一个颜色，加了规则仍然不同）。
- **不是减少覆盖。** 组件自己的元素（包括 fixed 的）和 teleport 内容照常比较。隐藏只在截图那一刻生效。能不能隐藏，看的是 DOM 上组件根的包含关系和 scopeId，不看位置或时机。
- **这是 HM-251、HM-253 的延续。**
  - HM-251 把比较对象收窄到组件自己的根；
  - HM-253 拿掉了组件外的 fixed、sticky 元素；
  - 本规则把剩下的组件外元素也拿掉。这些元素只能经由边缘的小数像素行，或者重叠、溢出，画进组件截图。

### 4. 影响面

- `queue/` 里有 recordVia 工单 50 张（47 张 `todo`，3 张 `regression`：`fair.signModal`、`sjz.newHome.resource`、`special.page1.jobNews`），现有基线 45 份。合入后，每份 recordVia 基线会在下一次门槛（或回归）时离线重算一次，之后按新做法比较。
- 非 recordVia 页面的基线和比较完全不受影响。
- 已经通过的 recordVia 页，什么情况下会翻为失败：去掉邻居以后，边缘行露出来的祖先背景两侧不同。比如原版独有的外壳祖先带了背景色（本页两侧的祖先在 `bgColor` 以外都是透明的，`body` 都是白色）。真出现了也是外壳的差异；合入后 `mergeRule` 自动开全量回归，回归失败会自动回退。
- 已知受益：本页。父页面 `talents/index` 下的其他子组件、其他父页面的最后一块，只要框边是小数，都会遇到同样的问题。
