### 1. 问题

门槛 `gate.1`：`load.html` 不同（长度 39338/39176），`load.pixel` 1.290%（上限 0.5%）。报告在 `$RESTORE_STATE/gate/page.portal.talents.talentnew.talentList-a1/`，原版两次运行结果相同，`unstable` 为空。

#### 1a. 像素：原版截图里叠着布局的固定头部

- 门户 `/talents/*` 的布局 homeView 渲染一个 Fragment：头部、`RouterView`、底部。所以原版 `main > *` 的候选依次是 `headerBox`、页面根 `bgBoxTop marB30`、页面自己的 `recommend`、`footCls flex`（`baseline.json`）。
- 头部是固定定位：

  | 文件:偏移 | 内容 |
  | --- | --- |
  | `legacy-dist/portal/assets/homeView.1783320636200.css:567` | `.headerCls[data-v-c9994972]{position:fixed;z-index:1000}` |
  | `legacy-dist/portal/assets/homeView.1783320636200.js:747` | 头部根 `{key:0,class:"headerBox"}`，scopeId `data-v-c9994972`（不是本页的 `data-v-0cf261ff`） |

- 页面根高 1372，视口 1080。元素截图要先滚动；滚动之后，固定头部画在视口顶部，落在页面根的 y≈295–385 这一条上。原版截图里有这一条，还原版没有：门槛把页面挂成顶层路由（HM-250、HM-779），还原版没有 homeView。
- 实测（用本页 HAR 只读重放原版，输出写在临时目录，已删除）：
  - 照现在的做法截图，与门槛里还原版的 `rest.png` 差 **1.290%**，与门槛报告一致；
  - 截图时只把头部设为不可见，差 **0.000%**。

  所以 1.290% 全部来自布局头部，不是页面画出来的。

#### 1b. HTML：原版 18 个 input 多一个空的 `style=""`

- 原版加载后，页面根里 18 个 `<input>` 带 `style=""`，还原版没有。这 18 个是：搜索框 `a-input` 1 个，两组 `a-radio-button` 共 16 个，分页快速跳转 `a-input-number` 1 个。
- 把两边的 `style=""` 去掉后，加载 HTML 逐字相同（39176/39176）。
- 交互之后，两边这 18 个 input **都**带 `style=""`，`final.html` 两边逐字相同。可见还原版的运行时也会留下它，区别只在截取的时候元素被打过几次补丁。
- 原 chunk 没有给这些组件传 style：

  | 文件:偏移 | 内容 |
  | --- | --- |
  | `legacy-dist/portal/assets/talentList.17833206362002.js:7547` | 搜索框 `l(r,{class:"boderinputse boderinputsecorlor",value:…,"onUpdate:value":…,placeholder:…,size:"large"})` |
  | `legacy-dist/portal/assets/talentList.17833206362002.js:8975`、`:9362` | 学历、工作经验两组 `l(K,{value:…,onChange:…})` 里的 `v(G,{class:"marR20",value:a.…})` |
  | `legacy-dist/portal/assets/talentList.17833206362002.js:13240` | 分页 `"show-quick-jumper":"",total:…,pageSize:…`，没有 style |

- `style=""` 是空声明块，渲染和没有 style 属性一样。没有选择器能区分它和「没有 style」：
  - `legacy-dist/portal/assets/*.css`、`legacy-dist/usercenter/assets/*.css` 和门户 js 里都搜不到 `[style`；
  - `hmrsfw-vue` 里唯一的 `[style` 在 TinyMCE 编辑器内容样式（`apps/uc/public/tinymce/skins/ui/oxide/content*.css`），写法是 `table[style*="border-width: 0px"]`，只匹配含这段文字的非空 style。

### 2. 改动

**empty-style**（`kind: tree`）：去掉空的（或只有空白的）`style` 属性。非空的 style 照常比较，元素的其他属性也照常比较。

- `44-motion-state` 里也有「空 style 视同没有」这一条，但它还会去掉过渡状态类和行内样式，范围更大。它从 HM-4 起停用待审，本单不启用它，也不改它。

**shell-layout-shots**（截图时的测量范围）：

- 只在原版一侧生效：`baseline.mjs` 把工单的 `scopeIds` 传给 `runPage`；`gate.mjs` 的还原版一侧不传，截图方式不变。
- `captureRoot` 截每个候选之前，把 `origSel` 下不带任何本页 scopeId 的兄弟元素及其内容设为 `visibility:hidden`，截完马上撤掉。门户上被隐藏的就是 homeView 的 `headerBox` 和 `footCls`。
- 不变的东西：
  - 只改可见性，布局不变；
  - DOM 树、innerText、浮层、请求都在隐藏之前取，内容和以前完全相同；
  - 页面自己的根照常截入，包括固定定位的（本页的 `recommend` 带本页 scopeId）。
- 没有任何候选带本页 scopeId 时什么都不隐藏，照旧截图。这包括没有 scoped 样式的页面（`queue/` 里 5 张）和根上不带工单 scopeId 的页面（48 份基线，比如 recordVia 子视图）。
- scopeId 只认 `data-v-` 加 8 位十六进制，拼进选择器前先校验。`queue/` 里 294 张页面单的 scopeId 全部符合。

### 3. 为什么不算放宽

- **像素阈值没变，比的仍是页面根的整张截图。** 拿掉的只是原版外壳（布局头部、底部）画在页面根上的部分。
  - 还原版在门槛里本来就没有这层外壳。
  - 外壳另有工单（`page.portal.talents.homeView`）。
  - 这和已有做法一致：外壳的请求（`30-shell-requests-portal`）、外壳 toast（HM-250）只从原版一侧扣掉。
- **不是减少覆盖。**
  - 页面自己的固定元素照常比较（用例 `gate-shell-shots` 第 1 项）。
  - 隐藏只在截图那一刻生效。
  - 能否隐藏，看的是 DOM 上本页 scopeId 这个确定的标记，不看位置或时机。
- **empty-style 只规范化渲染相同的写法。** 非空 style 一律比较（用例第 2 项）；`style=""` 和没有 style 的元素在两个应用里没有任何选择器能区分（第 1b 节）。
- **两条规则都不会让已通过的页面翻为失败。**
  - empty-style 两侧同样处理：原来相同的两份 DOM，处理后仍然相同。
  - 198 份基线分别用 `main` 和本分支的规则重算 `unstableKeys`，逐项相同。

### 4. 影响面与基线重录

**empty-style。** 198 份基线里，有 81 份（门户 46、用户中心 35）某个候选含空 `style=""`，规范化结果会变。这条规则只影响比对，不用重录。
