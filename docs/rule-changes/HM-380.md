### 1. 问题

本页的根节点是一个空列表的外层，高度为 0：

| 文件:偏移 | 内容 |
| --- | --- |
| `legacy-dist/portal/assets/scrollList.1783320636200.js:501`、`:528` | 根 `div.marT20.scrolls`，里面只有 `div.scrollContent` |
| `legacy-dist/portal/assets/scrollList.1783320636200.js:882` | `scrollContent` 的子项全部来自 `n.list` 的 `v-for`，没有别的内容 |
| `legacy-dist/portal/assets/scrollList.1783320636200.css:0` | `.scrollContent[data-v-9e281131]{max-height:680px;overflow-y:auto}`：没有最小高度，`.scrolls` 本身也没有尺寸声明（`:410` 起只有滚动条样式） |
| `legacy-dist/portal/assets/index.178332063620015.css` | `.marT20{margin-top:20px}`：外边距不占根的框 |
| `legacy-dist/portal/assets/index.178332063620095.js:7671` | 父页面把 `list: e.trendsList`（「大会动态」）传给本组件 |

基线（两次原版运行）和还原版拿到的 DOM 都是 `<div class="marT20 scrolls"><div class="scrollContent"></div></div>`：录制时 HAR 里这个列表为空。所以两侧的根都是 0 高。

`captureRoot`（`tools/gate/replay.mjs`，HM-4 起）在根的框为 0 时没法做元素截图，退回 `page.screenshot()`，截的是**整个视口**。视口里是父页面 `talents/conference` 的「关于大会」区和布局外壳，本组件一个像素都不在里面。

把基线 `shot.png` 和门槛 `rest.png`（`$RESTORE_STATE/gate/page.portal.talents.conference.scrollList-a1/`）用门槛同一个 `pixelmatch` 阈值 0.1 分块比：

| 区域 | 不同像素 |
| --- | --- |
| 整个视口，不错位（门槛报的数） | 22.537% |
| 导航条以下（y ≥ 300），不错位 | 23.188% |
| 导航条以下，原版下移 90px 再比（原版 y 390–1080 对还原版 y 300–990） | **0.000%** |
| 导航条及以上（y < 300），不错位 | 23.204% |

结论：

- 父页面内容两侧完全相同，只是原版整体低 90px。这 90px 就是外壳 homeView 的头部占位 `.headerBox{height:90px}`（`legacy-dist/portal/assets/homeView.1783320636200.css:516`，HM-253 第 1 节同一处），门槛的还原版不挂外壳（HM-250、HM-779）。
- 导航条以上是外壳头部本身（原版的天际线背景、职位下拉），属于外壳的工单。
- 同一父页面下的兄弟组件 abouts、swperSlides 有面积，走元素截图，像素差为 0。
- 页面代码无法修到通过：还原版的根和原版逐字节相同，差异全部在根外面。

### 2. 改动

**zero-box-shot**（截图时的测量范围）：

- 只在根的框没有面积（宽或高为 0，或根不渲染）时生效，两侧代码相同（`captureRoot` 原版、还原版共用）。有面积的根照旧元素截图，一个字节都不变。
- 不再截整个视口，改截**根实际绘制的内容**（`paintedBoxInPage`，在页面里算）：
  - 根所有可见后代元素的框（`getClientRects`）和文本框的并集。0 高的根里浮动、绝对定位、溢出的内容照样会画出来，这些都在框里；
  - `visibility` 不是 `visible` 的元素不算它自己的框，但它里面重新设为可见的后代照算；`display: none` 的子树不算；
  - 一个零面积的元素如果在那个方向上裁剪溢出（`overflow` 不是 `visible`），它下面的内容画不出来，不算。
  - 并集不为空：按这个框整页裁剪截图（与有面积的根超时后的退路同一个调用）。
- 并集为空（根什么都不画）：不截图，候选记 `blank: true`。
- 比对（`shotDiff`）：
  - 两侧都是 `blank`：像素差 0；
  - 一侧 `blank`、另一侧有图：按 100% 不同报 `pixel`，提示里尺寸写 `0x0`；
  - 两侧都有图：照旧 `pixelDiff`。
  - 原版两次运行一次 `blank`、一次有图时，`unstableKeys` 把 `load.pixel` 记为不稳定，和其他不稳定的像素项一样处理。
- **旧基线自动重算**：新基线记 `paintedBox: true`。没有这个标记、并且有 load 截图恰好是视口尺寸（1920×1080）的基线，`baselineFor` 走 HM-251 已有的 `refresh` 路径，用原 HAR 离线重算一次。真正就是视口大小的根，重算后截图方式不变，结果相同。

### 3. 为什么不算放宽

- **像素阈值没变，比的仍是根自己。** 拿掉的是根外面的父页面和外壳，它们另有自己的工单（`page.portal.talents.conference.index`、外壳 homeView）。这与 HM-251（比较对象收窄到组件根）、HM-253、HM-262（截图里去掉根外的固定元素和外壳）是同一个测量范围的问题，本规则补的是「根没有面积」这一种情况。
- **根画出来的像素一个不少。** 0 高的根溢出画出的内容仍在截图里，两侧照比；只有确实什么都不画的根才没有截图。
- **两侧同样处理，不对称就失败。** 一侧什么都不画、另一侧画了东西，按 100% 不同报出来，比原来更严：原来两侧都截视口时，一侧多画的一小块可能落在阈值以内。
- **结构和内容另有判据。** 根的 HTML、innerText、浮层、请求照旧比较，`blank` 只影响像素项。本页这些项一直全部一致。
- **与等价写法的关系。** 一个 0 面积、什么都不画的根，元素截图本来就是空的；视口截图是拿不到元素截图时的替代品，测到的是别的东西。把它规范为「空」，是同一件事的等价表示。
