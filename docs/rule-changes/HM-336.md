### 1. 现象

门槛报告 `$RESTORE_STATE/gate/page.portal.talents.information.newsList-a1/page.portal.talents.information.newsList/report.json`（规则版本 `8ada37b35e61`）只有一项失败：`load.html`，hint `… div.cus-pagination-box > div.ant-input-number > div.ant-input-number-input-wrap (offset 3064; lengths 3233/3224)`。

```
原版：<input … class="ant-input-number-input" role="spinbutton" step="1" style="">
还原：<input … class="ant-input-number-input" role="spinbutton" step="1">
```

长度差 9 正好是 ` style=""`。两次原版运行都有这一处；把两边的 ` style=""` 去掉后，`load.html` 逐字相同。`final.html` 两边本来就相同，而且两边的这个 input 都带 `style=""`。

### 2. 原因：门槛截图自己写进 DOM，取 HTML 的先后决定有没有

**Playwright 的截图默认隐藏光标。** `playwright-core` 1.64.0（`node_modules/playwright-core/lib/coreBundle.js` 第 22755–22770 行，`hideCaret` 段）：截图前对整页（`document` 和各 shadow root）所有 `input,textarea,[contenteditable]` 记下 `style.getPropertyValue("caret-color")`，然后 `style.setProperty("caret-color","transparent","important")`；截图后用记下的值 `setProperty` 还原。原来没有行内 style 的元素，还原值是空串，声明被删掉，但 `style` 属性留下来，变成 `style=""`。范围是整页，不只是被截图的元素。

**`captureRoot` 按候选逐个「先取 HTML、再截图」。** `tools/gate/replay.mjs` 第 75–100 行：对选择器匹配到的每个根候选，先 `outerHTML`/`domTreeInPage`，再 `el.screenshot()`。所以第 i 个候选取 HTML 时，前面 i 个候选已经截过图，整页的 input 都已带上 `style=""`。

**原版这条路由的页面根前面有一个外壳候选，还原版没有。** 原版选择器是 `main > *`（`tools/gate/common.mjs` `SITES.portal.origSel`），基线 `$RESTORE_STATE/baseline/page.portal.talents.information.newsList/baseline.json` 两次运行的 load 候选都是 `headerBox`、`marB30 main marT50`（页面根）、`footCls flex`。比对用的是第 2 个（`pickCandidate` 按还原版根的 class 取），取它的 HTML 时 `headerBox` 已经截过图。还原版选择器是 `#poc-main > *`，只有页面根一个候选，先取 HTML 后截图，所以 load 里没有 `style=""`。到 final 阶段，两边 load 时的截图都已经做过，所以两边都有。

**同类页印证。** 同样用 `cus-pagination`、原版 `main > *` 只有页面根一个候选的 `page.portal.train.trainList`（候选 `bgBoxTop marB30`）、`page.portal.sjz.news.newsList`（候选 `marB30 main marT30`），原版 load 没有 `style=""`，门槛通过。

所以这处差异与页面代码、原 chunk 都无关，是测量过程本身写进 DOM 的东西，有没有只取决于选择器在页面根前面匹配到几个元素。

### 3. 规则：`empty-style`

`rules/compare/47-empty-style.json`，`kind: tree`：去掉值为空白的 `style` 属性。其余一律照常比较：

- 有任何声明的 `style` 不动，包括 `caret-color: transparent !important;` 这类（用例第二项）；
- 其他空属性（`class=""`、`disabled=""` 等）不动；
- 元素、文本、属性顺序之外的一切不变。

**为什么是等价写法，不是放宽。** `style=""` 没有任何声明，不参与层叠，渲染与没有 `style` 属性完全相同。能区分两者的只有属性选择器 `[style]`：`legacy-dist/portal/assets/`、`legacy-dist/usercenter/assets/` 下的 CSS 和 JS 里搜不到 `[style`，原版和还原版都不用它。规范化同时作用在两边；像素比对不做任何处理，阈值不变。被认为相同的只有「同一元素，一边有空 style、一边没有」这一种情况。

**为什么不改截取顺序。** 改成「全部候选先取 HTML、再逐个截图」能让以后的运行不再产生这个属性，但 198 份原版基线都是按现在的顺序录的，页面根前面有外壳候选的页面，基线里已经带着 `style=""`，要全部重录才一致。规则同时覆盖已有基线和以后的运行，也覆盖 Vue 绑定先设后清留下的空 style（`:style` 由有值变成空对象时 Vue 删掉各条声明、保留属性），这两种写法渲染相同。
