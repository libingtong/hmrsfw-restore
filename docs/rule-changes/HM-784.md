## HM-784：`gate.mjs` 的 `[GATE]` 评论改用 `--content-stdin`

- 分支：`rule/hm-784-gate-comment-stdin`（基于 `main` `55b43cb`）。改动是一个提交 `fix(gate): [GATE] 评论正文经 stdin 传给 multica`，本文件另一个提交。
- 只改 `tools/gate.mjs` 里发评论的方式：`multica()` 多一个可选的 `input` 参数，`report()` 用 `--content-stdin` 发评论，不再往 `$RESTORE_STATE/gate/…` 写 `gate-comment-<pid>.md`。
- 合入 `main` 后，把同一个提交 cherry-pick 到 `restore/fast-lane`。两条分支上 `report()` 发评论的那一行和 `multica()` 完全相同（两边只差 `const failed = out.failed ?? []` 这一行，不在改动范围里），不会冲突。
- 提出：裁定员；复核：两个非 Anthropic 家族的复核员。

### 现象

从 10-18 起，multica CLI 默认拒绝工作目录以外的 `--content-file`（`multica issue comment add --help`：「The path must be inside the current working directory unless --allow-external-file is set」，MUL-4252）。`gate.mjs` 把评论文件写在 `out.diff`（即 `$RESTORE_STATE/gate/<页>-a<n>/`）或 `$RESTORE_STATE/gate/` 下，这些目录都不在门槛员的工作目录里，所以每次都会报 `comment failed`。元数据 `gate.<attempt>` 和 `advance` 不受影响，只是评论要门槛员手动补发（HM-232、239、249、251、253、255 等）。

### 为什么用 stdin

- 工具仓库里其他脚本发评论本来就走这条路：`tools/lib/multica.mjs` 的 `comment()` 用 `--content-stdin` 加 `input`，`tools/lib/fake-multica.mjs` 也只支持这种写法。
- 不需要临时文件，也就不会在调用方的工作目录（可能是 git 检出）里留下文件，进程中途退出时同样不会留下。
- 不用 `--allow-external-file`：这个开关本来是为了防止读到别的运行留下的旧文件。
- `execFileSync` 的参数是数组，不经过 shell，不存在 #4182 里 heredoc 把后面的参数吞掉的问题；`--output table` 照常生效。

### 不动的东西

门槛判据、比对逻辑、规则文件、归一化、阈值、元数据 `gate.<attempt>` 的内容、评论正文的格式，都没有改。

### 验证

用一个假的 `multica`（`MULTICA_BIN`，遇到 `--content-file` 就像新版 CLI 一样拒绝，遇到 `--content-stdin` 就记录 stdin），在工具仓库之外的目录跑 `node tools/gate.mjs --task t1 --wo entry.portal.E1`（没有基线，走 `{pending: "record"}` 分支，同样会调用 `report()`）：

| 版本 | 结果 |
| --- | --- |
| `main` `55b43cb` | `comment failed: … --content-file …/state/gate/gate-comment-<pid>.md … path outside cwd refused`，评论文件留在 `$RESTORE_STATE/gate/` 下 |
| 本分支 | `issue comment add t1 --content-stdin --output table`，stdin 为 `[GATE] PENDING record entry.portal.E1 a1: no baseline`，不写任何文件 |

两次的 `issue metadata set … gate.1` 调用完全一样。
