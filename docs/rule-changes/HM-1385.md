### 2. 证据：为什么 leave 过渡捕获到的不是「没有 style」

`motion-state` 规则（`stripMotion`，`tools/gate/rules.mjs`）原来对 appear/enter 和 leave 一视同仁：剥掉状态类和行内 style，什么都不留。这对 appear/enter 是对的——`node_modules/ant-design-vue/es/_util/collapseMotion.js:21-27` 的 `onAfterEnter` 把 `height`/`opacity` 清回 `null`，settle 后确实没有 style。但触发按钮不是靠 appear/enter 出现的新节点，是 `node_modules/ant-design-vue/es/upload/UploadList/index.js`（`HackSlot`，`appendAction` 插在 `<TransitionGroup>` 里）用 `v-show` 切换的，`node_modules/ant-design-vue/es/upload/Upload.js:316-317`（`renderUploadList(renderUploadButton, !!(children && children.length))`）把 `appendActionVisible` 绑定到「页面是否还在 slot 里传了触发按钮内容」。

`v-show` 包在正在跑的 `<Transition>`/`<TransitionGroup>` 里，走的是 `node_modules/@vue/runtime-dom/dist/runtime-dom.cjs.js:1314-1330`（两个 app 锁定的 Vue 版本都是 `3.3.4`）：

```js
updated(el, { value, oldValue }, { transition }) {
  if (!value === !oldValue) return;
  if (transition) {
    if (value) { transition.beforeEnter(el); setDisplay(el, true); transition.enter(el); }
    else { transition.leave(el, () => { setDisplay(el, false); }); }   // ← leave 完成的回调里才 setDisplay(el,false)
  } else { setDisplay(el, value); }
},
function setDisplay(el, value) { el.style.display = value ? el._vod : "none"; }
```

`value` 从 true 切到 false 时只调 `transition.leave(el, 回调)`——先跑 leave 过渡（状态类 + `collapseMotion` 的行内 `height`），**只有过渡完成的回调里才会 `setDisplay(el, false)`**，没有任何路径会在这个过程里把节点清成「没有 class 也没有 style」。本地用这两个 app 实际锁定的 Vue/ant-design-vue 包复现（`vite`/`esbuild` 起一个最小 Upload picture-card 页面，`max-count=1`，异步把 fileList 从 0 变到 1 个文件，Playwright 截取各时刻 DOM）：

```
[323.0ms] 初始（0 个文件）：<div class="...ant-upload-select-picture-card">...<div>upload</div></span></div>
[420.8ms] 文件变成 1 个：      <div class="...ant-upload-select-picture-card ant-upload-animate-inline ant-upload-animate-inline-leave-from ant-upload-animate-inline-leave" style="height: 104px;">...
[668.9ms] leave 进行中：       <div class="...ant-upload-select-picture-card ant-upload-animate-inline ant-upload-animate-inline-leave ant-upload-animate-inline-leave-active" style="height: 0px; opacity: 0;">...
[902.8ms] 结算：              <div class="...ant-upload-select-picture-card" style="display: none;">...
```

从头到尾只有「可见（无 style）→ leave 状态类 + height → `display:none`」三种态，没有第四种「leave 状态类消失但还没落到 `display:none`」的中间态。所以一个只带 leave 族状态类（没有 appear/enter 类）的 `ant-upload-select-picture-card` 元素，一旦这些类将来消失，唯一能落到的终态就是 `display:none`，不会是「没有 style」。

### 3. 规则改动

`stripMotion`：按状态类是 appear/enter 还是 leave 分支——leave 族（且不混 appear/enter）时，剥掉状态类后把 style 换成 `display: none;`（而不是整段丢弃）；appear/enter 分支不变（原来怎样还怎样）。不扩大匹配范围：仍然只认 `MOTION` 正则匹配到的状态类（`^([\w-]+)-(appear|enter|leave)(-(from|to|active|prepare|start))?$`），没有这些类的元素不受影响（empty-style 的单独处理也不变）。

### 4. 还剩一点没碰：「没有状态类也没有 style」那一种捕获态

同一次回归（`gate/runs/bf67f4e2c3e96071`）里，`page.uc.CorpAttestation` 的「代办人身份证照片」字段（`apps/uc/src/views/CorpAttestation.vue:388-414`，同样 `max-count=1`、同样的触发按钮）两次原版回放也逐字相同，捕获到的是**第三种态**：`<div class="ant-upload ant-upload-select ant-upload-select-picture-card">`，没有状态类，也没有任何 `style`——比对器会把它当「可见」，还原版是 `style="display: none;"`。这一页此刻确实有 1 个文件（`K.value.length<1` 为 `false`，两边代码逐字相同，见第 1 节），语义上触发按钮也应该隐藏，这一种态大概率也是同一条 `v-show`-in-transition 链路的某个更早或被打断的中间态；但我在本地复现（第 2 节同一个最小页面）只能稳定复现「可见 → leave 状态类 → `display:none`」这三种，复现不出「没有状态类也没有 style」这第四种——没有证据能把它钉死成「leave 链路的某个必然中间态」，也不能排除它恰好是「按钮真的应该可见」的真实差异被我误判。继续按 HM-1363 §2 的态度：不在这条规则里囫囵吞掉，留着，等下次命中、或者能在浏览器里实测出触发条件再处理。本单只处理第 0/2 节证据确凿的那一种态。

### 5. 为什么不算放宽

- **判据不变**：只给 `motion-state` 本来就认的「带 rc-motion 状态类」的元素，把终态从「丢弃 style」改成「按状态类是哪一族决定终态」；不认状态类之外的任何元素，像素阈值、请求判据、公共库清单都没动。
- **同一套组件代码，不是页面代码或版本差异**：两个 app 锁定的 `vue@3.3.4`、`ant-design-vue@3.2.20` 一字不差，`v-show`-in-transition 的行为是 Vue 核心运行时逐字确认过的（第 2 节引用），不依赖任何页面自己的逻辑。
- **范围封闭，没有扩大到第 4 节那种没有状态类的态**：规则只对「本来就带 leave 状态类」的元素生效；一个从没进入 leave 过渡、本该一直可见的元素不会被这条规则碰到。
