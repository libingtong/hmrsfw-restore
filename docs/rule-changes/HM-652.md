## HM-652：门户首屏轮播（slick）和 echarts 实例号造成的原版基线不稳定

- 分支：`rule/hm-652-slick-carousel`（基于 `main` `402a559`），每条规则一个提交：
  1. `rule(compare): slick-track-transition`：比对时去掉 `.slick-track` 行内 style 里的 `transition` 声明，文件为 `rules/compare/45-slick-track-transition.json`，实现在 `tools/gate/rules.mjs`；
  2. `rule(compare): echarts-instance-id`：`_echarts_instance_="ec_<数字>"` 的数字换成占位，文件为 `rules/compare/46-echarts-instance-id.json`。
- 合入 `main` 后，同样两个提交 cherry-pick 到工具仓库 `restore/fast-lane`，因为快速通道的录制和门槛用的是那条分支上的工具。两条分支的 `tools/gate/rules.mjs`、`rules/compare/` 相同，没有冲突。
- 提出：裁定员；复核：两个非 Anthropic 家族的复核员。
- 来源：HM-48 快速通道录制时，`record-page` 因原版基线两次回放不一致报 `unstable`（`ok = !unstable.length`），下列页面录不成：HM-604、HM-611、HM-612、HM-635。另外核对了同类可疑页 `xjhm.home.index`、`xjhm.home.advertTop`、`sjz.bigData.mobile.index`。
- 不动的东西：像素阈值、请求集合和请求序列的判据、HAR、公共库清单。停用的 `43-style-transition`（去掉所有元素的 transition）和 `44-motion-state` 保持停用，本单不用它们。

### 1. `.slick-track` 上的 `transition`

**现象。** HM-635（`talents.cityHome.helpCenter`）的 load 阶段、HM-604（`talents.cityHome.talentArea`）的 final 阶段，以及 HM-611（`region.skill.index`）`load.html` 这一项，两次原版运行的规范化 HTML 都只有一处不同（`$RESTORE_STATE/baseline/<id>/baseline.json`，按 HTML 标签切分后逐个比对）：

```
A: <div class="slick-track" style="width: 550px; opacity: 1; transform: translate3d(0px, 0px, 0px);">
B: <div class="slick-track" style="width: 550px; opacity: 1; transform: translate3d(0px, 0px, 0px); transition: -webkit-transform 500ms;">
```

`transform` 相同，各 slide 的类、`aria-hidden`、`data-index` 也相同，差别只在有没有 `transition`。

**原因：这是原代码里轮播库的写法。** 门户的轮播是 ant-design-vue 的 `a-carousel`，底层是 vc-slick，打包在 `legacy-dist/portal/assets/index.1783320636200.js`：

| 偏移 | 内容 |
| --- | --- |
| 557765 | 静止时的轨道样式 `getTrackCSS`：`{opacity:1,transition:"",WebkitTransition:""}`，加上目标位置 `transform: translate3d(left)` |
| 558381 | 滑动时的轨道样式 `getTrackAnimateCSS`（`PL=function(e){…}`）：在 `getTrackCSS` 的结果上加 `WebkitTransition="-webkit-transform "+speed+"ms "+cssEase` 和 `transition` |
| 571456 | `animationEndCallback=setTimeout(…, speed)`：`speed` 毫秒后把轨道样式换回静止样式 |

自动播放每 `autoplaySpeed + 50` 毫秒（默认 3050）滑一次。滑动开始时，目标位置的 `transform` 就已经写进 style，同时加上 `transition`；500 毫秒后 `transition` 被去掉。这几页只有一张 slide，或者轮播滑回原位，所以 `transform` 始终是 `0px`，只是快照有时落在这 500 毫秒里面，有时落在外面。

**还原版有同样的现象。** 现有门槛报告 `$RESTORE_STATE/gate/page.portal.cityHome.index-a1/…/report.json`，还原版 load 阶段的轨道是 `transform: translate3d(0px, 0px, 0px); transition: -webkit-transform 500ms;`，原版两次运行都是 `transform: translate3d(0px, 0px, 0px);`。两边用的是同一个库，只是快照的时刻不同。

**规则。** 只处理 class 里有 `slick-track` 这个词的元素，去掉它行内 style 的 `transition` 和 `-webkit-transition` 声明（写法与停用的 `style-transition` 相同）。其余一律照常比较：

- 轨道的 `transform`、`width`、`opacity` 都还比较，所以轮播停在哪一张仍然会比出来。如果还原版停在别的 slide，`transform` 不同，照样失败（测试 `tools/test/compare-rules-carousel.test.mjs` 的第二项）。
- 其他元素上的 `transition` 不动，包括 fade 模式下 slide 上的 `transition: opacity 500ms, visibility 500ms`（它一直存在）和页面自己写的 transition。
- slide 的个数、顺序、克隆、内容，以及 `slick-active`、`aria-hidden` 都不动。

**为什么不算放宽。** 规范化同时作用在原版和还原版上，被认为相同的只有「同一位置的轨道，一个正在滑、一个已经停下」这一种情况。行内 `transition` 只决定样式下一次变化时怎么过渡，不改变当前这一帧的渲染。像素比对不做任何处理，阈值不变。原来「两次基线不同」时，这个位置会被通配掩码（volatile mask）放过，什么都能匹配；现在两次基线一致，还原版必须逐字相同，反而比原来严。

### 2. `_echarts_instance_` 的值

**现象。** `sjz.bigData.mobile.index`（本单列出的可疑页）的 load 阶段，以及 `jobMarket.index` 的 load、final 阶段，两次运行只差一个属性值：

```
A: <div _echarts_instance_="ec_1792144146926" class="setSize" …>
B: <div _echarts_instance_="ec_1792144143116" class="setSize" …>
```

**原因。** echarts 在模块加载时记下当前毫秒数，`echarts.init` 给容器写的实例号就是这个毫秒数加上序号。偏移位于 `legacy-dist/portal/assets/index.1783320636200118.js`：

| 偏移 | 内容 |
| --- | --- |
| 318969 | `d5=+new Date-0` |
| 319119 | `r.id="ec_"+d5++`，随后 `p1(n,og,r.id)` 写进 `og="_echarts_instance_"`（偏移 318999） |

用户中心 `legacy-dist/usercenter/assets/index.175161560754527.js` 是同一写法（`CN=+new Date-0`、`i.id="ec_"+CN++`）。回放时页面时钟只固定到 HAR 录制的那一分钟，之后照常走，所以这个数每次运行都不一样，还原版也一样，因为两边用同一个 echarts。这个值只供 echarts 按 DOM 找回实例，不影响渲染。

**规则。** 类型是 `html` 替换，把 `_echarts_instance_="ec_<数字>"` 换成 `_echarts_instance_="ec_#"`。属性在不在、在哪个元素上都还比较：容器没有初始化 echarts，就没有这个属性，照样失败。其他形式的值不替换。测试是同一文件的第三项。

**为什么不算放宽。** 被认为相同的只有「两个 echarts 实例号」，它们由加载时刻决定，同一份代码每次运行都不同。图表本身（canvas、尺寸、容器样式）照常比较，像素阈值不变。

### 3. 其余问题的判断（本分支不处理）

| `xjhm.home.index`、`xjhm.home.advertTop` | 两次运行停在不同的 slide | **是自动播放的时间态，但规范化覆盖不全。** 差异是激活的是第几张：`slick-active slick-current`、`aria-hidden`、fade slide 的 `opacity`、轨道的 `transform`。advertTop 还有页面自己跟着轮播走的指示器（`li-item-active`，页面代码写的，不是库写的），以及 `load.pixel`。如果去掉激活下标，就不再比较「停在哪一张」，而 advertTop 照样不稳定。要解决，得让回放时的自动播放可以重复（例如快照前固定轮播进度），这是改回放流程，不是比对规范化，本分支不做。gate 对这类原版不稳定的位置本来就用通配掩码比，卡住的只是 `record-page` 的「`unstable` 必须为空」。 |
| `eMap.index`、`eMap.list`、`setUp.setupList`、`xjhm.bigData.statistics` | 地图瓦片、随机颜色、实时时钟和数据 | 与轮播无关，本单不处理，前后结果一样。 |

### 验证

- **全部原版基线**（`$RESTORE_STATE/baseline/` 下 114 份）：分别用 `main` `402a559` 和本分支的规则，对每份基线的两次运行重算 `unstableKeys`（脚本只读基线）。

  | 页面 | main | 本分支 |
  | --- | --- | --- |
  | `talents.cityHome.helpCenter`（HM-635） | `load.html` | 稳定 |
  | `talents.cityHome.talentArea`（HM-604） | `final.html` | 稳定 |
  | `region.skill.index`（HM-611） | `load.html`、`steps.requests` | `steps.requests` |
  | `sjz.bigData.mobile.index` | `load.html` | 稳定 |
  | `jobMarket.index` | `load.html`、`final.html` | 稳定 |
  | 其余 6 页不稳定的（见第 3 节） | 不变 | 不变 |

  没有哪一页由稳定变为不稳定，也没有新增不稳定项。
- **已有门槛报告**（`$RESTORE_STATE/gate/` 下 29 次运行）：只有 `cityHome.index` 含轮播，没有一份含 echarts。这页原来就失败，失败点在别处（`div.cityHomeCont1 > … > div.ant-col`），改动后仍然失败；还原版轨道上的 `transition` 差异被去掉了。
- **全量回归**：合入后由 `mergeRule` 开的 `rule-regression` 集成门槛对所有已通过页面跑。两条规则对两边做同一个变换，原来逐字相同的页面，变换后仍然相同。会变的只有两种：一是原来靠通配掩码通过的页面，基线变稳定后掩码没了，可能由通过变失败，这是变严；二是原来只因还原版快照落在滑动中、或只因 echarts 实例号而失败的页面，可能由失败变通过，这正是本变更要消除的误判。回归结果写在 HM-652。
- **测试**：新增 `tools/test/compare-rules-carousel.test.mjs`，3 项，其中包括反例：轨道停在别的 slide、别的元素上的 transition、没有初始化 echarts、不是 `ec_<数字>` 形式的值。

### 回退

每条规则一个提交，分别 `git revert`；也可以把规则文件的 `enabled` 改成 `false`。旧基线不用重录：门槛比对时按当前规则重新规范化。`record-page` 的 `unstable` 是录制时算的，所以 HM-48 要重录上面那几页，重算基线（`record-page … --baseline-only` 或整页重录）。
