## HM-1392：volatile mask 构造正则失败时不再让 gate.mjs 整体崩溃

- 分支：`hm-1392/volatile-mask-regexp-guard`（基于 `main` `3918f50`），一个提交。
- 触发单：HM-1392（排障单，裁定员）——HM-1154（`rule/hm-1132-defineoptions-name` 的全量回归，258 页）在 1.g7 轮报 `gateError`：`Invalid regular expression: /^<div data-v-x=""><div data-v-x="" style="position: relative;"><div class="jyEmap" data-v-x=""><div class="" data-v-x="" style="height: 900px;"><div style="width: 100%; height: 100%; overflow: hidden; position: relative; z-index: 0; background-color: rgb\(243, 241, 236\)`（`class: "other"`，exit=2，未写 verdict）。同一张单在此之前已经因「环境类」错误（后台时限、git fetch 失败）重跑了 3 次，这次是第 4 次重跑后新出现的、不属于环境类的失败。
- 提出：裁定员；复核：两个与裁定员不同家族的复核员（`tools/tick.mjs open-rule-review`）。
- 不动的东西：像素阈值、请求集合和请求序列判据、HAR、基线、公共库清单、`package.json`。不改 volatile mask 判定「原版自身竞态时该怎么算等价」的逻辑本身（LCS、公共前后缀、`[\s\S]*?` 占位），只给它已有的两个「放弃构造 mask」兜底（`a2.length*b2.length>4e6`、`holes>50`）补上第三个：构造出来的正则本身编译失败。

### 1. 定位：崩在哪一行、哪一页

`gateError.error` 被 `clip(error, 300)`（`tools/gate.mjs:761`，走 `[GATE] ERROR` 分支是 `.slice(0,300)`，`tools/gate.mjs:795`）截断到 300 字符，看不到 V8 报的具体原因（`Invalid regular expression: /…/: <reason>`的 `<reason>` 被截没了），但截断前的 300 字符逐字等于 `tools/gate/rules.mjs` 的 `normHtml` 对 `$RESTORE_STATE/baseline/page.portal.eMap.index/baseline.json` 的 `runs[0]` 算出的 `load.html` 字符串的前 300 字符（已验证：两者逐字节相同）。这条 html 是 `tools/gate/compare.mjs` 的 `maskRegex()` 在算「公共前缀」时原样 `esc()` 转义后拼进正则源码的那一段——定位到 `maskRegex()` 最后一行 `return new RegExp("^" + parts.join("") + "$");`（HM-1392 之前，`tools/gate/compare.mjs:175`）。

`page.portal.eMap.index` 两次独立原版回放的 `load.html`（人才地图页，`jyEmap` 地图挂件，百度地图瓦片/图层异步加载，位置和数量随每次回放不同）长度分别是 31012 和 47007 字符，按 tag 分词后公共前缀 331/494 个 token 之外的差异段落产生 9 个 `[\s\S]*?` 占位孔，拼出来的正则源码长度约 17.4KB。没有超过现有两个兜底的阈值（`a2.length*b2.length`≈16万，远小于 4e6；`holes`=9，远小于 50），所以两个旧兜底都没拦住；但这个 17KB、9 个非贪婪占位孔混着大段转义文本（地图挂件内联 style 里大量 `rgb(...)`、`px` 数值转义出的反斜杠）的正则，`new RegExp()` 在触发现场的 Node/V8 构建上编译失败（`Invalid regular expression`），在排障现场的沙箱 Node（v26.12.1）上同样的输入、同样的 `tools/gate/rules.mjs`（已验证切到触发时的 ruleSha `2d34d10e`也一样）却能编译成功——即这不是「正则写错了」，是 V8 把一个足够大、足够复杂的合法正则判定为「编译后太大」之类的内部限制，依赖具体构建，不保证能在任何机器上稳定复现。

### 2. 判定：问题在比对器，不在页面代码、基线或规则配置

- 两次原版回放逐字节不同（31012 vs 47007 字符），是地图挂件真实的渲染竞态（瓦片/标注异步加载，顺序和数量不固定），不是 HAR 或解密不稳定——不需要 `rerecord`。
- `maskRegex()` 本身就是为了处理「原版自身竞态」设计的（见 `tools/gate/compare.mjs:154` 注释），这次失败发生在它内部，不是某条 `rules/compare/*.json` 规则的判据问题，不需要改规则配置或放宽像素/请求阈值。
- 根因是这个函数原有的两个「放弃构造 mask，退回逐字比较」兜底没有覆盖「正则本身编译失败」这一种情况，导致异常从 `volatileMatch()` 一路往上抛，`tools/gate.mjs` 的 `judgeOne()`（只有 `try/finally`，没有 `catch`）接不住，一页的问题炸穿了整批 258 页的 `judgeOne` 循环，顶层只能记一条 `gateError` 然后整个 gate 进程退出——HM-1154 这一张单因此连续吃了 4 次重跑（背景时限、git fetch 失败各一次，加上这次），每次都要从头或分段重跑一遍 258 页。

### 3. 规则改动

只给 `tools/gate/compare.mjs` 的 `maskRegex()` 包一层 `try { return new RegExp(...) } catch { return null }`，和函数里已有的两个尺寸兜底（`a2.length*b2.length>4e6 → null`、`holes>50 → null`）行为完全一致：构造不出 mask，就不掩盖这段差异，退回逐字比较（这一页这一处会被正常报成一条 diff，交给门槛/裁定员按平常流程处理，不是静默判通过）。不改 LCS、分词、转义、占位符的任何逻辑，不新增、不放宽任何等价判据；不改调用方 `volatileMatch`/`compareRuns` 的其它行为。

### 4. 为什么不算放宽

- **判据不变**：第三个兜底和原有两个兜底是同一件事——「这段差异安全地算不出 mask，就不算等价」，不是新增一种「算等价」的情况。
- **不影响其它页面**：只有在正则真的构造/编译失败时才触发，其余页面的 mask 构造和匹配结果字节不变（见第 6 节的全量 compare 测试）。
- **触发现场的后果是更保守，不是更宽松**：没有这个兜底时整批 258 页的回归直接崩掉，连「正常失败」都报不出来；有了兜底之后，这一页这一处差异会被正常地报成失败（如果原来会被 mask 掉的话，现在反而更严格），其余 257 页的结果不受影响。

### 5. 验证

- 新增 `node --test tools/test/compare-volatile-mask-guard.test.mjs`（2/2）：用两条原版 run 和一条不匹配两者的还原 run 构造出一定会走到 `volatileMatch` 的场景，临时把全局 `RegExp` 换成一个必抛错的假构造器，断言 `compareRuns` 不崩溃、把该字段正常计入 `failed`（和「control」用例——真实 `RegExp` 时同样的输入走 mask、`failed` 为空——对照，证明兜底只在构造失败时才改变结果）。
- `node --test 'tools/test/compare-*.test.mjs'`（42/42，含 `compare-root-pick`、`compare-volatile-canvas`、所有 `compare-rules-*`，无回归）。
- 用触发现场的真实基线数据（`$RESTORE_STATE/baseline/page.portal.eMap.index/baseline.json` 的两条 `runs`）跑 `project()` + 手工复刻的 `maskRegex` 逻辑，确认公共前缀的前 300 字符逐字节等于 `gateError.error` 截断前的内容（定位证据，见第 1 节）；分别用触发时的 ruleSha（`2d34d10e`）和当前 `main` 的规则跑过，两者在本机都能正常构造出正则（没有复现触发现场的编译失败，符合「依赖具体 V8 构建」的判断）。

### 6. 合入后

- `mergeRule` 自动开 `purpose=rule-regression` 全量回归。
- HM-1154 不需要重新录制或改基线；合入后对它 `--regate`，这次即使再次遇到 `page.portal.eMap.index` 这一类大竞态页面，`maskRegex` 构造失败也只会让这一页这一处正常计入该页的 diff（或维持已有两个兜底同样的「退回逐字比较」结果），不会再让整批 258 页崩掉。
