### 1. 原 chunk 中的证据

`legacy-dist/portal/assets/vue-countup-v3.es.1783320636200.js`（单行）：

- `:1:7324` `w(r,l=>{l&&a("finished")})`：`finished` 侦听只发出事件，不调用 `options.onCompleteCallback`。
- `:1:187` 起 `Object.getOwnPropertyDescriptors`、`Object.getOwnPropertySymbols`、`Object.prototype.hasOwnProperty`……：esbuild 的 `__spreadValues` / `__spreadProps` 降级展开辅助函数。

npm 上两个版本的 `dist/vue-countup-v3.es.js`：

| | 1.4.0 | 1.4.2 |
|---|---|---|
| `finished` 侦听 | `watch(finished, (flag) => { if (flag) { emits("finished"); } })`，与原 chunk 一致 | 在侦听里先调用 `d.options.onCompleteCallback()`，再 `m("finished")`，与原 chunk 不一致 |
| 对象展开 | `__spreadValues` / `__spreadProps` 辅助函数，与原 chunk 一致 | 原生 `...d.options`，与原 chunk 不一致 |

结论：原包打进来的是 1.4.0（HM-1166 也核对过 1.3.0 与 1.4.0 产物相同，1.4.1 起改了行为）。hmrsfw-vue 实际锁定的也是 1.4.0。清单写 1.4.2 是笔误。

### 2. 为什么不算放宽

清单的 `npm` 段只用来登记页面可以导入哪些 npm 包（`tools/check-imports.mjs` 读的是键，不读版本）。这次只改版本号，让清单和锁定版本、原包指纹一致：可导入的包集合不变，门槛判据不变，没有页面因此由不过变成过。
