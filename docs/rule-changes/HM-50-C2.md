## HM-50-C2：接口模块的命名空间浅拷贝导出（`jobCompany` 的 `o`）由 `restore-api.mjs` 生成

分支 `rule/api-namespace-copy`。来源：`docs/rule-changes/HM-46-findings.md` 第 C2 节（S1 = HM-45）。

### 裁定

由**生成工具**补，不归入口或共享层工单手写：`o` 是对本模块请求函数的机械变换，和这些函数本身一样由 `restore-api.mjs` 从原 chunk 生成，清单里标 `owner: "script:restore-api"`。

- `tools/restore-api.mjs`：`parseApiChunk()` 新增 `copies`。条件：一个**导出的**绑定，值是 esbuild 的对象展开（`__spreadValues` 帮助函数 `p({},ns)`，或直接写成 `{...ns}`），`ns` 是 `Object.freeze(Object.defineProperty({__proto__:null,k:fn,…},Symbol.toStringTag,{value:"Module"}))` 形式的模块命名空间对象，并且每个成员都是本 chunk 的请求函数。生成 `export const o = { getCompanyInfo, … }`，键名用原包的键名，值是还原后的函数。按作用域解析绑定（这个 chunk 的命名空间和 6 个函数声明在顶层 await 包装函数内部）。
- `tools/registry-cleanup.mjs`：给已有接口文件追加缺失导出时，用同一段生成代码（`copySource`），不再写 `// TODO:restore 导出名 o 不是接口函数`。
- `tools/registry.mjs`：这类导出在清单里写 `owner: "script:restore-api"` 和成员说明；接口文件里有了 `export const o` 之后，状态自动变为 `restored`。

清单不手改，由 `registry.mjs` 生成。门槛和归一化规则都没有动。

### 等价依据

原 chunk `legacy-dist/portal/assets/index.1783320636200117.js`（单行，字符偏移）：

- 1283 起：`b=Object.freeze(Object.defineProperty({__proto__:null,getCompanyInfo:t,getRecommendTalentList:u,izAlreadySubmitCompany:a,queryCompanyInfo:s,submitNewGuideCompanyInfo:m,verifyCompanyInfo:l},Symbol.toStringTag,{value:"Module"}))`
- 1510 起：`_=p({},b)`；文件开头 `p=(s,a)=>{for(var t in a||(a={}))z.call(a,t)&&d(s,t,a[t]);if(f)for(var t of f(a))R.call(a,t)&&d(s,t,a[t]);return s}`，即 esbuild 的 `__spreadValues`
- 末尾：`export{…,_ as o,…}`

`p({},b)` 复制 `b` 自身可枚举的字符串键和符号键。`Symbol.toStringTag` 由 `defineProperty` 定义，不可枚举，不会被复制，所以 `o` 就是一个普通对象，带 6 个可枚举、可写、可配置的键，指向同一组函数。

用原 chunk 的 `p` 和 `b` 与生成的对象字面量逐项对比（node 实测）：自身键及其顺序、原型（`Object.prototype`）、是否冻结（否）、`Object.prototype.toString`（`[object Object]`）、每个属性描述符、每个值的函数身份，全部相同。

还原版：hmrsfw-vue `main` 的 `apps/portal/src/api/api-117.ts` 就是 `restore-api.mjs` 的输出。用本分支重新生成，与现有文件的差异只有新增的 3 行：

```
// 原包 `_=p({},b)`：本模块 6 个接口函数的命名空间对象 b 的浅拷贝，键名是原包的键名
/** 原压缩名 _，导出名 o */
export const o = { getCompanyInfo, getRecommendTalentList, izAlreadySubmitCompany, queryCompanyInfo, submitNewGuideCompanyInfo, verifyCompanyInfo };
```
