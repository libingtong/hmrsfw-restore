## HM-1379：`page.portal.fair.webFair.NumVideo` 基线回放在 root 步骤找不到根，根因是静态图回放答成 JSON 而不是图片

- 分支：`rule/hm-1379-static-img-not-in-har`（基于 `main` `1abd9ff`），提交：
  1. `rule(gate)`：`tools/gate/har.mjs` 对命中不到 HAR 的静态图请求（`STATIC_IMAGE_PREFIX`）返回 1×1 空白 GIF，而不是统一的 JSON `NOT_IN_HAR` 桩；新增 `notInHarResponse`，`--selftest` 加两条用例；
  2. 本文。
- 触发单：HM-1379（arbitrate，裁定员）——`baseline.mjs` 用 HM-1373 a5、HM-1380 a6 两次独立录制的 HAR 回放原版，都在 root 步骤（`{"clickSel":"img.defaultImg","root":true}`）报 `original page root ([data-v-3f3c6a40]…) not found`。离线复现由门槛员在 HM-1417（只读，保留 tmp 现场）完成，裁定员没有 `RESTORE_ASSETS`，这条规则变更基于 HM-1417 的复现结论提出。
- 提出：裁定员；复核：两个与裁定员不同家族的复核员（`tick.mjs open-rule-review`）。
- 不动的东西：
  - 像素阈值；
  - 请求集合和请求序列判据（`tier` 仍是 `path`/`body`/`not-in-har`，不比较）；
  - 除 `/jeecg-system/sys/common/static/` 外的全部请求：`NOT_IN_HAR` 的 JSON 文本、`status`、分支逻辑都没变；
  - `rules/compare/` 的 DOM 归一化规则；
  - 公共库清单、HAR、基线、`queue/`。

### 1. HM-1417 的复现结论（证据）

门槛员在 HM-1417 用 HM-1380 的草稿 + 现有 HAR（28 条）离线回放 `baseline.mjs`（临时去掉 catch 的 `rmSync` 保留 tmp 现场，核对后删除未提交），结论（[原评论](mention://issue/01a16f8d-97d3-758a-98a1-8e2a1e9b1452)）：

- 数据链路全部命中：`xfJobFair/queryById` 命中 HAR，解密后 `result.videoList` 长度 1；`getDictValueByCodeAndItems?labels=…,web_fair_detail_num_ad` 命中；`getArticleListByTypeIds`（取资讯封面）、`getArticleListNoCheck` 都命中。入口图渐进渲染的判断条件 `videoList.length>0` 成立，`img.defaultImg` 确实出现在 DOM 里（只有 1 个，没有被其它元素覆盖）。
- 入口图的 `src` 正是 `getArticleListByTypeIds` 响应里的封面路径：`/xf-api/jeecg-system/sys/common/static/temp/2025/2/12/<hash>.jpg`。这条 **GET 请求在 HAR 里没有条目**（录制没有把图片存成二进制），`har.mjs` 对这个前缀既不记日志也不报错，统一答成 `NOT_IN_HAR` 的 JSON 文本。
- `<img>` 把 JSON 文本当图片字节解码失败：`complete=true`，`naturalWidth=0`，渲染盒 0×0；Playwright 的 `target.click({timeout:5000})` 等不到可操作的元素，5 秒后超时，点击没有发生，`[data-v-3f3c6a40]` 从未挂载。
- 同页另外 3 张同前缀的图（`temp/2025/7/25`、`fair/2026/10/22` 等）同样被答成 JSON 桩，只是没有谁需要点它们，所以没暴露——这不是 NumVideo 一页的数据问题，是这一类请求在回放里普遍存在的问题，`rerecord` 不会改变 HAR 缺二进制图片这件事,所以两轮重录（HM-1373 a5、HM-1380 a6）复现的是同一个根因。

### 2. 原 chunk 证据：入口图没有显式宽高，解码失败就会塌成 0×0

`legacy-dist/portal/assets/detail.17833206362003.css`：

```
.defaultImg[data-v-54a2c6b3]{max-width:200px;max-height:200px;border-radius:10px}
```

只有 `max-width`/`max-height`（上限），没有 `width`/`height`。`<img>` 的渲染盒在没有显式尺寸时取决于解码出来的固有尺寸；`detail.*.js` 里入口图和 `NumVideo` 组件都由同一个条件 `((...).videoList?.length)>0` 控制渲染（`legacy-dist/portal/assets/detail.17833206362004.js`），数据链路本身没问题（第 1 节已核对），问题只在图片这一条请求回放的字节内容。

### 3. 改动

`tools/gate/har.mjs` 的 `routeApi`（`baseline.mjs`、`gate.mjs` 共用，`tools/gate/replay.mjs` 的 `runPage` 两侧都经过它）：

- 新增 `STATIC_IMAGE_PREFIX = "/jeecg-system/sys/common/static/"`（复用原有日志跳过逻辑已经在用的同一前缀，不是新引入的边界）和 `notInHarResponse(path)`：命中不到 HAR 时，这个前缀下的请求回一个写死的 1×1 透明 GIF（`image/gif`），其余路径照旧回 `NOT_IN_HAR` 的 JSON。
- `routeApi` 里 `if (!m.entry) return r.fulfill(...)` 改为调用 `notInHarResponse(p)`，不再对所有路径硬编码 `application/json`。

**为什么不选「改交互脚本，点别的元素」**：这是门槛员在 HM-1417 给出的另一个选项，但 `tools/gate/replay.mjs` 的 `step()` 当前不支持 `force` 一类跳过可操作性检查的标志，加这个标志本身也是工具改动；而且只换掉 NumVideo 一页的点击目标治标不治本——同一个 `/common/static/` 回放缺口会在下一张需要点图片的页面上原样重现。改 `routeApi` 一处，对所有用到这类静态图的页面（无论原版还是还原版）都生效。

### 4. 为什么不算放宽

- **判据不变**：改动只决定「HAR 没有的这一条请求，回放时的字节是什么」，不碰比较逻辑、阈值、请求序列判据。`tier` 仍然是 `not-in-har`（现在加了一个不参与比较的 `log` 跳过项，和改动前对 `/common/static/` 的处理一致）。
- **两侧同一处理**：`routeApi` 是 `baseline.mjs`（原版）和 `gate.mjs`（还原版）共用的同一个函数，这条改动对两边一视同仁，不会让原版和还原版出现新的不对称。
- **范围封闭**：只匹配 `/jeecg-system/sys/common/static/` 这一个已经被日志逻辑特殊对待的前缀；其它所有未命中请求（API、写请求等）的 `NOT_IN_HAR` 文本、状态码分支一字不变。
- **不是为了让某一页通过而改**：这个缺口影响的是任意页面里任意一张没被录进 HAR 二进制的 `/common/static/` 图片，NumVideo 只是第一个因为交互脚本需要点它而暴露出来的页面；修完之后，这类图片在原版和还原版的回放里都会从「JSON 当图片」变成「能正常解码的空白图」，不改变任何像素比较的结论（空白图和加载失败的图在当前比对规则下都不参与像素阈值判断，只是现在双方几何尺寸能对得上）。

### 5. 验证

- `node tools/gate/har.mjs --selftest`：7/7 通过（含新增两条：静态图前缀回图片、API 路径回 JSON 不变）。
- `node --test tools/test/ws-replay.test.mjs tools/test/record-write-guard.test.mjs tools/test/api-inventory.test.mjs tools/test/gate-interact-ref.test.mjs`：22/22 通过，无回归（这四个文件覆盖了 `routeApi`、HAR 装载、写接口拦截和交互脚本来源，是改动半径内最相关的既有用例）。
- 离线对照（本文第 1 节的数据，不跑浏览器）：`notInHarResponse("/jeecg-system/sys/common/static/temp/2025/2/12/<hash>.jpg")` 改前（模拟旧逻辑）回 `{contentType:"application/json", body:'...not in HAR...'}`，改后回 `{headers:{"content-type":"image/gif"}, body: 29 字节 GIF}`；任意 `/xf-api/...` 下非该前缀的路径（如 `job/licenseFree/xfJobFair/queryById`）改前改后都回同一份 `NOT_IN_HAR` JSON，没有变化。
- 本改动没有 `RESTORE_ASSETS`，无法在本机跑一次真正的 `baseline.mjs`/`gate.mjs` 端到端回放验证 NumVideo 是否真的能通过 root 步骤；下一步需要门槛员或录制员用现有 HAR 实跑一次确认（见「合入后」）。
