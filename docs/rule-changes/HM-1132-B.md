## HM-1132-B：工单漏登 defineOptions({name}) 形态的主组件（`page.portal.xjhm.bigData.newBigdata`）

- 分支：`rule/hm-1132-defineoptions-name`（基于 `main` `0d6a355`），提交：
  1. `fix(work-orders)`：`tools/scope.mjs` 的 `componentsOf`；用例 `tools/test/scope-components.test.mjs`；重生成后的 `queue/page.portal.xjhm.bigData.newBigdata.json`；
  2. 本文。
- 提出：裁定员；复核：两个非 Anthropic 家族的复核员。
- 来源：HM-1068 快速通道退场时这一页被 held，原因是「queue 工单 components 只登记了 manaLoginModal，漏登没有 __name 的主组件 big-screen-view-xygsBigdata（原 chunk 2 个组件）；self-check components 不过。需改工单（work-orders.mjs 生成逻辑）后重生成」。
- 不动的东西：门槛、比对和归一化规则、阈值、公共库清单、`check-components.mjs`。

### 1. 原 chunk 中的证据

`legacy-dist/portal/assets/newBigdata.1783320636200.js`：

- `:1:2396` `Rt=st({__name:"manaLoginModal",emits:["cancelClick"],setup(…` → `Ut=St(Rt,[["__scopeId","data-v-31156f5e"]])`
- `:1:9218` `Oa=st({name:"big-screen-view-xygsBigdata"}),Ja=st(_t(lt({},Oa),{setup(T){…` → `zt=St(Ja,[["__scopeId","data-v-866f9cbf"]])`，文件末尾 `export{…,zt as default}`

第二个就是 `<script setup>` 加 `defineOptions({ name })` 在不支持对象展开的目标下的编译结果：先单独生成只有 `name` 的对象 `Oa`，再用 `__spreadProps(__spreadValues({}, Oa), { setup })` 合进组件。它是这个 chunk 的默认导出，也就是页面主组件。

`componentsOf` 原来只认两种写法：带 `__name` 的对象，或者同一个对象里有 `name` 和 `setup`/`render`。`Oa` 里只有 `name`，按「路由、`push` 参数一类的普通对象」跳过了，所以工单 `components` 里只有 1 个组件，`check-components` 要求交付 1 个 `.vue`，而正确的还原有 2 个。

### 2. 改动

只有 `name` 的对象被赋给变量 `O`，且 chunk 里有 `X=…(…({},O),{setup|render…` 时，把它记为组件，名字取 `name`，位置取 `X` 的定义处。这样下面已有的 scopeId 逻辑就会找到 `X` 的 `_export_sfc` 包装（`data-v-866f9cbf`）。结果按源码位置排序，原来的顺序本来就是源码顺序。`check-components` 的 `pageMain` 取最后一个组件作为主组件，排序后仍然是默认导出。

### 3. 影响面

- 扫描 `legacy-dist/*/assets/*.js`，只有 `newBigdata.1783320636200.js` 用了这种写法（`({},X),{setup|render` 且 `X={name:"…"}`）。
- 先用 `main` 原样跑一次 `node tools/work-orders.mjs --app <hmrsfw-vue>`，作为基准（`main` 上本来就有 51 个文件与生成结果不同，都和本改动无关，不在这个分支里）。加上改动后再跑一次，和基准相比，只有 `queue/page.portal.xjhm.bigData.newBigdata.json` 变了：`components` 和 `scopeIds` 各多了一项。
- 门槛判据不变。改动让工单如实反映原 chunk 的组件数，`check-components` 按原包的 2 个组件要求交付，没有放松。

### 4. 验证

- `node --test tools/test/scope-components.test.mjs`：2/2 通过。覆盖：newBigdata 的两个组件和各自的 scopeId；只有 `name` 的普通对象仍然不算组件。
- `node --test tools/test/work-orders.test.mjs`：通过。`gate-page-scope.test.mjs` 的 `target=_blank` 用例在 `main` 上同样失败，是浏览器计时问题，与本改动无关。
