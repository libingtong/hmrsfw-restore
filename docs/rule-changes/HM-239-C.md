### 现象

门槛报告是 `$RESTORE_STATE/gate/page.portal.talents.eMap.index-a1/…/report.json`。把规范化 HTML 按标签切分后逐个比对，差异几乎全在地图瓦片层：`<div style="position: absolute; overflow: visible; z-index: -100; …">` 下的一串 `<img src="https://apimaponline<n>.bdimg.com/tile/?qt=vtile&x=…&y=…&z=15…">`。三次运行（原版两次、还原一次）都是同样的 45 张瓦片，只是顺序不同：

```
原版 1：(5082,2566) (5083,2566) (5084,2566) (5083,2567) (5081,2566) (5083,2565) …
原版 2：(5083,2566) (5082,2566) (5084,2566) (5083,2565) (5081,2566) (5083,2567) …
还原  ：(5083,2566) (5083,2565) (5084,2566) (5082,2566) (5083,2567) (5082,2567) …
```

本页的正式基线是 10-18 19:33 用 HM-239（B）的回放重录的。它的两次原版运行，以及备份 `$RESTORE_STATE/baseline.bak-20261019-hm239/` 里的旧基线，load 和 final 的原始 DOM 树都不同，差别同样只在瓦片顺序。

### 原因：瓦片在各自下载完成时才插进 DOM

两边用的是同一个库：vue-baidu-map-3x 从 `api.map.baidu.com` 加载百度地图 JS API v3.0。瓦片的创建代码在 getscript（`https://api.map.baidu.com/getscript?v=3.0`）偏移约 152717 处：

```
e=C("img"); … g.left=c[0]+"px"; g.top=c[1]+"px"; … this.hb=e; this.src=b; …
this.hb.onload=function(){ … if(i.hb&&!Sb(i.hb)&&f.Mb){ f.Mb.appendChild(i.hb); … } … }
```

每张瓦片的 `<img>` 先建好，位置写进 `left`、`top`，但要等它自己的 `onload` 触发才 `appendChild` 到瓦片层 `f.Mb`。所以兄弟顺序就是图片下载完成的顺序，每次运行都可能不同。原版自己就有这个竞态，两次原版运行已经互不相同。瓦片都是绝对定位，位置由各自的 `style` 决定，DOM 顺序不影响画面，像素比对是 0 就说明了这一点。

域名分片不是随机的：本页 270 张瓦片（3 次运行 × load/final × 45 张）全部满足 `apimaponline((x+y) mod 4)`。所以 `src` 不需要处理，原样比较。

### 规则

`baidu-tile-order`（`tree`）的做法：

- 一个元素的子节点全部是百度瓦片图时，按瓦片的 `(z, y, x)` 排序，相同时再按 `src` 排。瓦片图指 `img`，且 `src` 匹配 `^https?://[\w-]+\.bdimg\.com/tile/\?`。
- 其他一律不动：
  - 有哪些瓦片照常比较。缺一张、多一张、换成别的瓦片都会失败（测试第二项）。
  - `src` 原样比较，包括域名分片、`z`（缩放级别）和 `udt` 版本。
  - `style` 原样比较：瓦片放在屏幕上哪里，由 `left`、`top` 决定。
  - 只要容器里混有任何不是百度瓦片的子节点，顺序就不动（测试第三项）。别的 `img` 列表、别的元素列表都不排序。

### 验证

- 测试 `tools/test/compare-rules-baidu-tiles.test.mjs`：3 项全过。
- 真实基线：本页新基线和旧基线的两次原版运行，load、final 的原始树都不同；按 `loadRules()` 规范化后完全相同。
- 门槛报告离线重放：对 10-18 19:35 那次的报告，只把瓦片按 `(z, y, x)` 排序，`src` 不动。排序后还原版和原版剩下的唯一差异，是搜索面板外面那层 `</div>` 的位置（`delete ['</div>']` / `insert ['</div>']`）。这正是页面修正 `b6f927a` 改的地方：规则没有放过它，它要靠修页面来解决。

### 为什么不算放宽

被认为相同的只有一种情况：同一个瓦片层里，同一组瓦片，各自的位置、地址都一样，只是插进 DOM 的先后不同。这个先后由网络决定，原版自己两次就不一样，而且不影响画面。原来遇到这种情况，两次原版之间不同的片段由通配掩码放过（什么都能匹配），还原版和两次原版都不同的片段则直接失败。现在两次原版先排成同一个顺序，还原版的瓦片集合、地址、位置必须逐个相同，比原来严格。像素比对、阈值都不变。
