### 1. 问题：两侧绝对地址只差端口

原 chunk 用 `self.location` 作基准拼绝对地址，再取 `.href` 写进 DOM：

| 文件:偏移 | 内容 |
| --- | --- |
| `legacy-dist/portal/assets/index.178332063620066.js:3135` | `new URL("/xjhm/innovation/cydj_icon.jpg",self.location)` |
| 同文件 `:3198`、`:3261`、`:3324` | `cyzx_icon.jpg`、`grdk_icon.jpg`、`qydk_icon.jpg`，写法相同 |
| `legacy-dist/portal/assets/statistics.17833206362002.js:15742` | `Jt={0:new URL("/assets/lll.1783320636200.png",self.location).href,…` |

还原版逐字保留了这个写法；按需编译时 `gate-build-assets-url`（HM-778）也把 `new URL("./x", import.meta.url)` 改写成 `new URL("<构建 URL>", self.location)`，与 `vite build` 产物一致。所以两侧 DOM 里都是 `http://<回放服务器>/…`。

回放服务器是门槛自己起的：原版 `tools/gate/serve.mjs` `listen(0, "127.0.0.1")`，还原版 `tools/gate/appserver.mjs` `server: { port: 0, host: "127.0.0.1" }`。端口每次随机，基线录制时的端口和门槛运行时的端口必然不同。HM-295 门槛报告（`$RESTORE_STATE/gate/page.portal.region.innovation.index-a1/…/report.json`）：

- 原版 `style="background: url(&quot;http://127.0.0.1:55844/xjhm/innovation/cydj_icon.jpg&quot;) …"`
- 还原版 `style="background: url(&quot;http://127.0.0.1:54451/xjhm/innovation/cydj_icon.jpg&quot;) …"`

四个图标、load 和 final 两个阶段都只差这 5 位端口。`replay.mjs` 的 `openedTarget` 对新开页面已经按同样理由只比路径（HM-797：「两侧本地端口不同，只比路径」），DOM 这边还没有。

### 2. 改动

`rules/compare/47-local-origin.json`，`kind: html`，一条替换：`http://127\.0\.0\.1:\d+` → `http://127.0.0.1:#`。`normHtml` 对原版和还原版都套用，基线文件不用重录。

### 3. 为什么不算放宽

- **只抹掉门槛自己引入的变量。** 端口不是页面代码决定的，是门槛起服务器时操作系统分配的。原站真实运行时两侧是同一个 origin，在这里它们本来就应该相等。
- **URL 其余部分照比。** 协议、主机、路径、参数都还在比较串里；绝对地址和相对地址（`/a.png`）仍然不同，`localhost`、`https` 不被替换；属性名、所在元素、在不在都照常比较（用例第 2 项）。
- **原包从不引用 `127.0.0.1`。** `grep -rl 127.0.0.1 legacy-dist/` 为空，所以替换只会命中回放 origin，不会吃掉页面内容。
- **不改阈值、不改判据、不改数据。** 像素阈值、请求比对、HAR、交互脚本都没动。

### 4. 影响面

扫了 `$RESTORE_STATE/baseline/` 全部 198 份基线（只读）。含 `127.0.0.1:<端口>` 的有 13 份：

- **出现在比对的 DOM 里（本规则生效）5 份**，都来自上面的 `new URL(…, self.location)`：
  - `page.portal.region.innovation.index`（本单）：4 个 `_icon.jpg` 背景，load/final；
  - `page.portal.xjhm.bigData.statistics`、`page.portal.zcyz.bigData.components.pieRader`、`pieCommon`、`scrollList`：`img src` 的 `lll.1783320636200.png`。
- **只出现在 `errors` 的报错堆栈里 8 份**（`UserAdminJobPlacement`、`livejob.detail`、`livejob.components.commentItem`、`talents.index.index`、`talents.index.jobFair`、`talents.information.newsList`、`uc.collage.studentApply`、`uc.gongfuWorkshop.jobPosting`）：报错不进 html 比对，结果不变。

规范化对两侧做同一个替换，原来相等的串替换后仍相等，所以已通过的页面不会因此变失败；只会让上述 5 页的端口差异不再报出。

**用 HM-295 的报告重放**：对 `report.json` 里两侧 load/final 的 html 套上本规则，带端口的差异块从 8 处降到 0；剩下 load 9 处、final 13 处都是 swiper 版本差异（`swiper-watch-progress` 类、`swiper-pagination` 在 wrapper 前后、slide 的 `margin-right` 位置、final 停在哪张 slide），由公共库升级单 HM-800（门户 swiper 锁到 8.0.1）处理，不在本规则范围内。
