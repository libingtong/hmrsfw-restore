## HM-1432 / HM-1433：原版空渲染页，load 阶段没有根节点

- 分支：`rule/hm-1432-empty-render-load`（基于 `main`），每条规则一个提交：
  1. `rule(gate): empty-render-load`：`tools/baseline.mjs`（`wo.emptyRender` 时跳过「原版根节点未找到」的硬失败，写 `baseline.json.emptyRenderLoad`）、`tools/gate/compare.mjs`（`bothRootless` 扩到 `load` 阶段，仅在 `baseline.emptyRenderLoad` 为真且两侧原始候选都是空占位符时生效）、`queue/page.uc.autoLogin.json`、`queue/page.uc.login.json`（标 `emptyRender: true` + 证据），用例 `tools/test/compare-root-pick.test.mjs`；
  2. 本文。
- 提出：裁定员；复核：两个非 Anthropic 家族的复核员。
- 来源：HM-1381（登录页三件套的后续）。`page.uc.autoLogin` → HM-1432（录制工单 a2，`01a17015-c91a-794c-bf06-9f573b11e4b4`），`page.uc.login` → HM-1433（录制工单 a2，`01a17016-000f-7da7-b093-256013850dec`）。两单录制本身都成功（匿名 / portal-handoff 模式按 HM-1381 的裁定正常工作），`baseline.mjs` 在算原版基线这一步报 `original page root (#app > *) not found`。
- 不动的东西：归一化规则（`rules/compare/`）、像素阈值、请求集合和请求序列判据、HAR、公共库清单、`origSelOf`/`REST_SEL`，以及所有其它页面（包括已有的 `recordVia`/`rootAfterSteps` 页面）的比对方式。只对显式标 `emptyRender: true` 的工单生效，且仍要求两侧「原始候选」本身是空占位符，不靠 class 匹配出的派生 `empty` 字段判断（见第 2 节「避免什么」）。

### 1. 问题

两个页面的原 chunk `setup()` 在 load 阶段固定渲染空（`render` 函数返回 `null`），不是录制/回放的问题：

| 工单 | 原 chunk:位置 | 证据 |
| --- | --- | --- |
| `page.uc.autoLogin` | `legacy-dist/usercenter/assets/autoLogin.1751615607545.js:1` | `setup(J){...;return(a,e)=>null}`：整个组件只在 `y.query.token` 存在时发请求（`getSysUserByToken`、字典查询等）、算完身份后 `r.push("/"+e)` 跳转；没有 `query.token` 时什么都不做；渲染函数固定是 `null`，和有没有 token 无关。 |
| `page.uc.login` | `legacy-dist/usercenter/assets/index.175161560754526.js:1` | 两层组件都固定渲染 `null`：内层 `index`（`data-v-080fd7af`）`setup(s){return e(String),c(),i(()=>{}),o(),e({...}),console.log("URL中移除token",a(...)),(t,n)=>null}`（只有一行调试 `console.log`，没有任何请求）；外层包装组件 `setup(s){return(t,n)=>(p(),u(l))}` 只是渲染内层组件 `l`，内层渲染 `null`，所以外层最终也是空。 |

`baseline.mjs` 对所有工单统一要求 load 阶段必须有根节点（`tools/baseline.mjs` 原第 113 行 `if (!c0 || c0.empty) throw ...`），对这两页，`录制员`两次重录（HM-1432/HM-1433，a2）结果一致：HAR 和交互脚本都没问题，原版就是没有根节点、`page.uc.login` 连请求也没有。门槛的「页面必须有根」假设对这类页面不适用——这正是 `tools/gate/compare.mjs` 已经给 `final` 阶段开过的口子（HM-1278，`resumeAnalysisReport` 关闭弹窗后两侧都没有 `final` 根，判定「同状态，不算失败」），只是之前没有覆盖到 `load` 阶段。

### 2. 改动（只对标 `emptyRender: true` 的工单生效）

- **`baseline.mjs`**：新读 `wo.emptyRender`。原来无条件 `throw`；现在只有 `wo.emptyRender` 为真、且本次 load 阶段**每一次**原版回放的候选都是空占位符（`replay.mjs captureRoot` 在找不到元素时写的 `{tree:null, empty:true, ...}`，不是某一次偶然找不到）才放行，继续写 `dom.html`/`text.txt`（都是空字符串）和 `baseline.json`，并在 `baseline.json` 顶层记 `emptyRenderLoad: true`，供门槛读。任何原版回放**偶尔**找到真实内容（哪怕只有一次）仍然 `throw`——不信任标记本身，只信观察到的数据，和 HM-251 的「找不到就失败，不回落」一致。
- **`gate/compare.mjs`**：`bothRootless(ph)` 新增 `ph === "load"` 分支：`baseline.emptyRenderLoad` 为真，且还原侧和原版两侧「原始候选」（不是按 class 匹配出的 `O`/`R` 派生 `empty`）全部是空占位符时才算「两侧同状态，不是 bug」。命中时跳过 `load.root`、`load.baseline`（原第 253 行）、`load.render`（原第 254 行）三处失败；`load.html`/`load.text` 两侧都是空字符串，按原有逐项比较逻辑天然相等，不需要特殊处理。
  - **为什么不能用派生的 `empty` 字段**：`O`/`R` 的 `empty` 由「这一侧有没有和另一侧同 class 的候选」算出（`project()`），class 不匹配本身就会把 `empty` 置真，和「原版真的什么都没渲染」是两件事——如果直接复用它，原版明明有真实内容、只是 class 和还原侧不同，也会被误判成「两侧都空」从而放过真实差异。改动直接看 `rest.load.candidates`/`baseline.runs[].load.candidates` 的原始 `empty` 标记，不经过 class 匹配这一步。用例第 3、4 项专门测了这个边界（原版有真实根 vs 还原侧空；两次原版回放一次空一次有内容）。
- **工单**：`queue/page.uc.autoLogin.json`、`queue/page.uc.login.json` 各加 `emptyRender: true` 和一条 `emptyRenderNote`，写明原 chunk 位置和一句话证据（本文第 1 节的内容搬了一份过去，方便工单自身可读）。

### 3. 为什么不算放宽

- **判据和阈值一个没动**：html、text、overlay、请求集合与序列、像素、已知差异的比较逻辑完全不变；两侧真的有内容时该怎么比还是怎么比（用例第 2、3、4 项）。
- **只认「两侧同状态」，不认「还原侧偷懒」**：还原侧渲染了真实内容而原版没有（或反过来）仍然失败（`load.root`/`load.render`），不会因为标了 `emptyRender` 就被放过——标记只影响「原版这一步是不是允许算出一个合法的『无根』基线」，不影响比较本身的判据。
- **只对两张显式标记、有原 chunk 证据的工单生效**：别的页面（包括大多数页面本来就有内容、以及已有的 `recordVia`/`rootAfterSteps` 页面）比对方式完全不变；`bothRootless("load")` 的两个前置条件（`baseline.emptyRenderLoad` + 两侧原始候选都是空占位符）缺一个都不生效。
- **可回退**：每条改动一个提交，全量回归异常可按提交单独回退，不影响已经通过的其它页面。

### 4. 验证

- 新增 `tools/test/compare-root-pick.test.mjs` 用例「original load root genuinely empty on every run」，4 个断言：
  1. 两侧 load 都是空占位符、标了 `emptyRenderLoad`：无失败；
  2. 还原侧渲染了真实内容：`load.root` 失败，不被放过；
  3. 原版两次回放都是真实内容（标记本不该这么用，但验证比对器不盲信标记）、还原侧空：`load.render` + `load.root` 失败；
  4. 原版两次回放不一致（一次空一次有内容）：不对称，不触发 `bothRootless`，按原有逻辑报 `load.baseline` + `load.render`。
  另加一条：不标 `emptyRenderLoad` 时，同样两侧都空仍然按原逻辑报 `load.baseline` + `load.render`——必须 `baseline.mjs` 先显式放行才行。
- `tools/test/` 全量：见本单提交记录里的 `node --test tools/test/` 结果（后续全量回归由 `mergeRule` 自动触发，覆盖全部已通过页面）。
