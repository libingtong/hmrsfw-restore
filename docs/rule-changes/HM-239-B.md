## HM-239（B）：百度地图 IP 定位在门槛回放里给固定应答

- 分支：`rule/hm-239-baidu-localcity`（第 1 轮基于 `main` `c12aad7`，两票 approve 后自动合并与 HM-245、HM-295 改过的 `runPage` 冲突；已变基到 `main` `f87e2e1`，冲突只在 init script 那一行的上下文，`main` 新增的代码原样保留，规则本身没改），一条规则一个提交：`rule(gate-replay): baidu-localcity`。实现在新文件 `tools/gate/thirdparty.mjs`，`tools/gate/replay.mjs` 的 `runPage` 多一行 `addInitScript`；测试在 `tools/test/gate-localcity.test.mjs`。
- 合入 `main` 后，同一个提交 cherry-pick 到工具仓库 `restore/fast-lane`。新增的 import 和 init script 两行，上下文在两条分支上相同（`restore/fast-lane` 只是少了 coverage 那几行），不会冲突。
- 提出：裁定员；复核：两个非 Anthropic 家族的复核员。
- 来源：HM-239（`page.portal.talents.eMap.index`，快速通道）。HM-779 修好根节点选择以后，这一页剩下的失败全都来自百度在线 IP 定位。
- 不动的东西：比对规则 `rules/compare/`、像素阈值、请求集合和请求序列的判据、HAR、公共库清单、`origSel`。地图脚本、底图、控件、标注和 `BMap.Geolocation` 都不处理，照常走百度。

### 现象

还原侧 4 次门槛中有 3 次加载阶段缺列表请求 `POST /xf-job/job/licenseFree/freeCompanyPositionPageList`（10-15 第 1 次、10-18 02:02、03:36 那次的两次运行）。只有 10-18 01:48 那次的请求和步骤全部通过，而那次和 02:02 那次之间代码没有变。03:36 的报告（`$RESTORE_STATE/gate/page.portal.talents.eMap.index-a1/…/report.json`）里，还原页的地图已经建好（BMap 的各层 `div` 和 `canvas` 都在），但中心停在 0,0：没有底图，也没有百度版权行，所以 innerText 是 74 字符，原版是 147 字符。步骤里的列表请求也缺少经纬度。原版基线是 10-16 录的，两次运行都拿到了定位。

### 原因：页面的第一个列表请求要等百度在线 IP 定位

两边的代码一样，原 chunk 是 `legacy-dist/portal/assets/index.178332063620096.js`：

| 偏移 | 内容 |
| --- | --- |
| 7080 | `function dt({BMap:t,map:o}){…p.value.lng===0){let n=function(B){p.value.lng=B.center.lng,p.value.lat=B.center.lat,…};var s=new t.LocalCity;s.get(n)}}`：地图 ready 后用 `BMap.LocalCity` 取所在城市，回调里设地图中心 |
| 7351 | `function oe(t){…t.target.getCenter().lat===0?setTimeout(()=>{oe(t)},500):ct(t)}`：中心还是 0 就每 500 毫秒再等一次；有了中心才进 `ct`，按地图范围发 `freeCompanyPositionPageList` |

还原页 `apps/portal/src/views/talents/eMap/index.vue` 的 `onMapReady`、`onMapZoomEnd` 逐句对应。`BMap.LocalCity#get` 是百度地图 JS API 的 IP 定位服务：先懒加载 `othersearch` 模块，再向百度发 JSONP。它回不回、什么时候回、回哪个城市，取决于跑门槛这台机器的网络。门槛的 `routeApi` 只应答 `/xf-api/`，HAR 是靠 XHR/fetch 钩子录的（`tools/capture-har.js`），录不到 JSONP，所以 HAR 里没有百度的请求，重录也补不上。

### 规则

和 `page.clock.setSystemTime`（把页面时钟固定到 HAR 录制的那一分钟）一样，`runPage` 给原版和还原两侧都装同一个 init script：

- 页面里每个 `BMap.LocalCity` 实例的 `get(cb)` 都在下一个任务里回调 `cb({center: new BMap.Point(lng, lat), level, name})`，城市固定为哈密市中心（`FIXED_CITY`，BD-09 坐标）。不发网络请求。
- 挂钩点是百度脚本自己建命名空间的两处赋值：`var z=window.BMap||{}` … `z.LocalCity=ng`（getscript 偏移约 250706），以及加载器给 `window.BMap` 的赋值。实例仍是原来的 `LocalCity`（`instanceof` 成立，构造参数照传）。`get` 是实例自己的属性，`othersearch` 模块以后装上真正的 `get`，也不会覆盖它。
- 不用百度地图的页面完全不受影响：没有 `window.BMap`，就什么也不做。`BMap` 的其他成员一律不碰。

### 真实 SDK 上的验证

用这个分支（变基前后各跑一次）对原版跑了基线，输出到临时目录 `node tools/baseline.mjs page.portal.talents.eMap.index --out <临时目录> --no-coverage`，没有覆盖正式基线。结果：

- 两次运行在加载阶段都有 `POST /xf-job/job/licenseFree/freeCompanyPositionPageList`，`unstable` 为空。
- 页面根的文本带百度版权行，说明地图按固定中心正常加载了底图。
- 10 个步骤都没有报错。步骤里列表请求的 `latitude`、`longitude` 就是 `FIXED_CITY`，地图范围由它算出，两次运行完全一样。

### 为什么不算放宽

这条改的是两侧的输入，不是比对。原版和还原版拿到同一个城市，就像它们拿到同一份 HAR、同一个时钟。比对时什么都不放过：html、text、请求集合、请求序列（含经纬度）、像素，判据和阈值都不变。原来定位有时回、有时不回，还原版只能碰运气；现在每次都回同一个城市，还原版的地图中心、地图范围和请求参数都必须和原版逐项相同。没有这条，这几项根本没法稳定地比。

### 影响面和后续

- 用到 `BMap.LocalCity` 的只有 `page.portal.eMap.index`（已分段，`seg.portal.eMap.index.1/2`）、`page.portal.talents.eMap.index` 和公共组件 `shared.portal.GetLocationMap`（排在 `BMap.Geolocation` 失败之后作兜底）。它们都还没有通过门槛。用 GetLocationMap 的 `sjz.job.jobList`、`LookForJob.CorpDetail` 两页，基线加载阶段不出地图，也不发带经纬度的请求。全量回归里已通过的页面不应受影响。
- 合入并 cherry-pick 后，`page.portal.talents.eMap.index` 的正式基线要用新的回放重跑（`node tools/baseline.mjs page.portal.talents.eMap.index`，只读 HAR 和登录态），因为旧基线里的经纬度来自录制机器当时的网络。重跑后再送门槛。其他地图页录制时自然用上新回放。
- 没有处理的：地图底图和版权行仍然来自百度在线服务。底图版本更新会改像素，版权行会改文本，到时候应该在原版和还原版上同时出现、同时失败。如果出现了，另开单讨论地图资源的录制和回放。
