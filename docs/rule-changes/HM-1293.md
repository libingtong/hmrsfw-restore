  2. 本文。
- 提出：裁定员；复核：两个非 Anthropic 家族的复核员（`tick.mjs open-rule-review`）。
- 来源：`page.portal.fair.signModal`（recordVia `page.portal.sjz.fair.fairList`，recordPath `/fairList?type=web`）。HM-1292 录制员三次 `record-page` 都在 `baseline.mjs` 报 `original page root ([data-v-484c8df1]:not([data-v-484c8df1] *)) not found`；同一页面上根选择器加载时匹配 0 个，点「报名参会」打开弹窗后匹配 3 个。HM-948 下 12 张小组回归只差这一页的基线。

### 1. 两侧都是 `v-if`，加载时组件不存在

原版：`/fairList?type=web` 的网络招聘会列表 `legacy-dist/portal/assets/list.17833206362008.js`（`page.portal.sjz.fair.webFair.list` 的 chunk）

- `1:10815`：`e.signShow?(o(),s(Wa,{key:0,visible:e.signShow,zphInfo:e.zphInfo,onOkclick:l.okSign,onCancel…})):…`，即 `<signModal v-if="signShow">`；
- `1:3507` 起：点「报名参会」后 `checkIzDishonesty` 返回 `result=="false"` 才 `e.zphInfo=l,e.signShow=!0`；
- 组件本身 `legacy-dist/portal/assets/signModal.1783320636200.js`：渲染函数 `T("div",j,[u(re,{…})])`，`j={ref:"globalModal"}`，根是带 scope id `data-v-484c8df1` 的 `div`，`a-modal` 用 `get-container:false` 渲染在它里面。

还原版（hmrsfw-vue `integration` `0ee1427`）：

- `apps/portal/src/views/sjz/fair/webFair/list.vue:139-141`：`<SignModal v-if="state.signShow" :visible="state.signShow" …>`，`:308` 在同一判断后置 `state.signShow = true`；
- `apps/portal/src/shared/signModal.vue:174`：根 `<div ref="globalModal">`，`<style scoped>`（门槛据此取还原侧 scope id）。

所以「加载时没有组件的根」是原版本身的状态，还原版是同一写法，不是还原缺失。现有逻辑却在两处把它判成失败：

1. `baseline.mjs` 要求第一次运行加载时第一个候选非空，原版基线录不出来（就是 HM-1292 的报错）；
2. 即使有基线，`compareRuns` 对两侧都只有 `empty` 占位的加载阶段报 `load.baseline`（原版没有根）和 `load.render`（还原版根为空）；占位的截图是整屏（父页 + 原站外壳），拿来比的也不是组件。用 `main` 的 `compare.mjs` 对「两侧加载时都无根、交互后根相同」的输入跑一遍：`['load.baseline', 'load.render']`。

### 2. 规则 `recordvia-root-after-steps`

只在同时满足以下条件时生效（`compare.mjs` `afterSteps`）：

- 工单是 recordVia（`compareRuns` 的 `inParent`，`gate.mjs` 对 recordVia 页传入；`baseline.mjs` 看 `wo.recordVia`）；
- 还原版这次运行加载时没有任何真实根候选（只有 `empty` 占位）；
- 原版**每一次**运行加载时都没有真实根候选，且**每一次**运行交互后都有根候选（`rootAfterSteps`）。

此时：

- 加载阶段不报 `baseline` / `render`，不比加载截图（两侧都是占位整屏）；加载时的浮层、请求集合、打开的页面照旧比（父页的，与其他 recordVia 页相同）；加载 HTML / 文本两侧都是空占位，照旧比，相等；
- 交互后照旧比 HTML、文本、浮层、请求序列、步骤报错；还原版交互后没有根时新增 `final.render` 失败（不会因为没有根而被当成「两侧相同」）；
- `baseline.mjs`：`dom.html` / `text.txt` 取第一次运行交互后的第一个根，`baseline.json` 写 `rootAfterSteps: true`（只是标记，门槛不读，判定按两次运行本身）；
- `unstableKeys`：两次原版运行都满足 `rootAfterSteps` 时不比加载占位截图（否则占位整屏的差异会让 `record-page` 判为 unstable）。

不满足时一律照旧：任何一侧加载时有根（还原版提前挂载 → `load.root` 或 `load.baseline`；原版加载时有根而还原版没有 → `load.render`）；有一次原版运行交互后没有根；非 recordVia 页。用例逐条覆盖。

为什么这不是放宽：两侧状态相同的判断与 HM-1278 `final-rootless-both` 同类，只是在加载阶段、且要求交互后有组件可比。没有放宽任何阈值。像素：弹窗类组件在任何页都不做像素比对（`replay.mjs` 截图前 `HIDE_OVERLAYS` 隐藏 `.ant-modal-wrap`），交互后阶段本来就不截图；本规则只是不再拿父页整屏占位冒充组件截图。组件内容由交互后的 DOM（规范化 HTML 含 class / style）、文本、弹窗浮层文字比对。

### 3. 影响面

`queue/` 里 recordVia 工单 50 张：49 张已有基线，两次运行加载时都有根（逐张读 `$RESTORE_STATE/baseline/<id>/baseline.json`），`rootAfterSteps` 对它们为假，判定不变；唯一没有基线的就是 `page.portal.fair.signModal`。同名含 Modal 的另一张 `page.portal.answer.passwordModal` 加载时就有根，不受影响。非 recordVia 页不受影响（`inParent` 为假）。
