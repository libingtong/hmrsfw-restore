# 调度与派单

## 1. 怎么拆单

| 单类 | 粒度 | 模型 |
| --- | --- | --- |
| 入口包 | 按区域拆（启动、路由、全局注册、请求层、外壳等），每单不超过约 30KB；入口组件每单最多 3 个 | 强模型 |
| 共享组件 | 每个共享 chunk 一单；多组件 chunk 拆成每个组件一个 `.vue` | 强模型 |
| 小模块 | 每个应用一单 | 强模型 |
| 页面 | 一页一单；< 5KB 的页面 3–5 张打成一单；≥ 30KB 的页面分段 | 默认模型；便宜模型要先过小样本重测，只接 < 30KB 的页面 |
| 录制 | 一页一单，标题 `[record] <工单id>` | 默认模型 |
| 升级、规则变更、排障、集成回归 | 由调度或裁定员按需建 | 强模型 / 门槛员 |

轻量模式用阶段子单：G0 摸底 → G1 引擎接入 → 公共库一批 → 页面每批约 20 页（或按功能区分 A/B/C/D 批） → R 规则变更 → 每批一张复核单 → 收尾单（合并各批分支、全量验证、交付最终分支）。收尾单先放在 `backlog`，等前面各单都到 `in_review` 后，由最后交付的那一单把它改成 `todo`。

## 2. 派单顺序

- 入口包、共享组件、页面三条线同时派，入口包和共享组件的优先级更高，能更早减少顶替。
- 同一优先级里大页先派（按 `kb` 降序）。
- 每个还原员保持「正在跑 + 1 张排队」。
- 录制要领先于还原：给录制员也保持「正在跑 + 1 张排队」，按页面派单的顺序录。

## 3. 防误派（派单前逐条检查）

- 只派 `status: todo` 的工单：`npm`、`regression`、`segmented` 都不派，`held`、`superseded`、已 `merged` 的也不派。
- `missing` 非空的不派，先补清单。
- 共享库和 npm 工单不派录制单，也不进入等录制的流程。
- 分段单的最后一段，等前面各段都合入后再派。
- 已经关掉的任务（`cancelled`、`done`）不能被 `advance` 或 `--regate` 重开。
- 创建要幂等：每张任务有创建键，先查账本再建；建任务时先放 `backlog`、不指派，写完元数据后再一次性设状态和负责人（这一步才会启动运行）。
- 同一张工单有两张以上未结束的任务且不是双派，就报「重复派单」，由裁定员决定留哪张。
- 派单前核对项目隔离：项目 id、目录、测试域名、仓库（见 `01-project-setup.md`）。

## 4. 停止条件（触发后暂停派新单，建排障单交给裁定员，处理完 `resume`）

- 连续 5 次同类门槛失败（类别 = 阶段 + 第一个失败检查）。先看是不是同一张任务，见 `06-troubleshooting.md`。
- 集成门槛失败率超过 10%。
- 某个「生成家族 × 复核家族」组合审计满 10 次后，漏检率超过 10%。
- 一小时内出现 3 次无法归类的运行失败。
- 默认还原家族（以及已启用的便宜档）全部在冷却中。
- 同一个异常每轮都在重复报（例如元数据写入失败）：先暂停定时自动化，别让它每轮都开一张排障单。

## 5. 运行失败的处理

- 限流或额度不足：这个智能体冷却 30 分钟，改派同家族的另一个智能体，没有就派给路由的下一个候选。
- 环境类失败：同一智能体重跑一次，再失败就改派。
- 无法归类：报 anomaly。失败类别映射表要用实际看到的报错原文去更新，不要靠猜。

## 6. 审计抽检

按生成家族的档位抽检：冷启动（审计不满 20 次）50%，平时 20%，漏检率高时加严到 100%，表现好时放宽到 10%。复核员要选和这条分支上所有参与者（还原员、修正员）都不同家族的。没有可用的复核员时不要卡住，页面照常 `done`，但要写明跳过了审计。

## 7. 只有这些事升级给人（`blocked` + 指派负责人）

| 类别 | 例子 |
| --- | --- |
| 需要人在场 | 登录态过期要重新登录、需要其他身份的测试账号、测试环境重置、造数、加密的真实场景验证 |
| 钱 | 用量超出预算、要新增付费模型或运行时 |
| 合规与安全 | 反编译的著作权或合同问题、密钥或个人数据已经进了仓库或评论、需要访问生产环境 |
| 智能体无法达成一致 | 规则变更单两轮复核都不同意；需要业务知识才能做的取舍（例如某个页面是否已经废弃） |

其余待决事项按项目默认值执行（写在配置的 `escalation.defaults` 里），记进每日摘要，人可以随时推翻。

## 8. Multica 任务约定

- 状态：`todo` 已派单 → `in_progress` 执行中 → `in_review` 已交付、等门槛、等录制或在审计 → `done`（由智能体按机器判据设置）；`blocked` 只用于上一节的事项；`cancelled` 用于双派落选和作废的工单。
- 评论标签：`[RECEIPT]`、`[FIX]`、`[GATE]`、`[AUDIT]`、`[RECORD]`、`[REDO]`、`[BLOCKED]`、`[ARBITER]`。脚本只读元数据，评论是给人看的。
- 元数据：对象写成 JSON 字符串，大的值压缩写入；整张单所有键加起来不超过 8KB；键名不能带 `@` 或中文。
- 还原员、修正员、门槛员不 @ 任何智能体，也不把状态改成 `done`。交接一律通过 `handoff.mjs` 和 `tick.mjs advance` 完成。
- 改工具或引擎代码时开 PR，作者不自己合并。
- 每日摘要发在「调度日志」任务里：完成数、回退数、规则变更、已知差异登记、按默认值执行的决定、用量。
