# 新还原项目的启动单模板

在 Multica 新建项目后，按顺序建下面几张单。项目描述先写好「固定目标」和「强制隔离」两段（见 `project-notes.md` 模板），每张单都会继承。

## G0 摸底、环境自检、Git 基线

- **运行模式**：in_place（这时还没有 git 基线，不能切 worktree）。
- **要做**：
  1. 环境自检：`node`、`npm`、`git` 的版本；能否访问引擎仓库；测试站首页能否打开（只发一次 GET，不登录）。
  2. Git：目录不是仓库就 `git init`，加 `.gitignore`（`node_modules/`、`*.har`、`.auth/`、`.env*`），基线提交 `baseline: original build output`；然后把项目资源切到 worktree 模式。
  3. 摸底：构建工具（不是 Vite 就停下并说明）、各类 chunk 的数量、路由、接口、加密、多租户、样式；已有成果盘点；引擎哪些能直接用、哪些要改。
  4. 写 `project-notes.md` 初稿和分批计划（放在评论里即可）。
- **禁止**：除第 2 步外，不修改目录里任何已有文件；不登录，不抓接口数据。

## G1 引擎接入与工单流水线

- **要做**：拷入上游引擎（记下指纹，剔除别的项目的数据）→ 写配置和钩子并校验 → 离线重建映射 → 生成 `registry/`、`queue/`、`out/maps|hints/`、`tests/interact/` 骨架 → 已有成果标为 `regression` → 写 `project-notes.md`。
- **验收**：`validate-config` 通过；引擎测试能跑；映射数字和 G0 一致，或逐项解释差异；已有测试和构建保持通过；生成物里没有密钥、个人信息或 HAR 数据。

## 公共库批次（入口包、共享组件、请求层）

- 强模型执行；先做外壳、请求层、全局注册，后做共享组件。
- 每单交付都要过 `self-check` 和整站构建。

## 页面批次 G3-A … G3-N（每批约 20 页）

- 每批一张单，批内一页一个 worktree，可以并行派子智能体。
- 每页：录制 → 还原 → 自检 → 门槛；失败按修正 → 重做 → 裁定的顺序处理。
- 每批配一张**复核单**，指派给不同模型家族的复核智能体。

## R 规则变更（按需）

- 只做等价规范化，附正反例测试和原 chunk 证据；配复核单。

## 收尾

- 先放 `backlog`。前面各单都到 `in_review` 后，由最后交付的那一单改成 `todo`。
- 合并各批分支 → 回写回执 → 全量验证（引擎测试、构建、全部页面的门槛）→ 汇总状态表和阻塞清单 → 交付最终分支，由人合并，或交给工作区负责合并的角色；作者不自己合并。
