# Vue 生产包还原

这套方法来自 `hmrsfw-restore` 引擎和工作区里几个已经跑过的还原项目：一个两应用、近 300 页的全自治流水线，一个 20 页、已完成的单应用项目，以及几个 uni-app、JeecgBoot 项目。它只讲**通用方法**。项目专属的东西（目录、测试域名、机器、技术基线、账号身份、加解密）一律放进该项目自己的 `restore.config.json` 和 `docs/project-notes.md`，不写进本 skill，也不要从别的项目抄过来。

## 交付标准（任何规模都一样）

还原完成的意思是：

1. **真源码**：标准工程（入口、路由、配置、真实依赖都在），页面是能直接改的 `.vue` SFC，命名可读，共享逻辑放在公共库里。只整理编译后的 ESM、给旧 bundle 套一层包装、只把流程配好，都**不算完成**。
2. **真构建**：`dev` 能热更新，`build` 真的从新源码编出 SFC。运行时不依赖旧产物，旧产物只用来做比对。
3. **行为等价**：用原站录下的 HAR 回放，原版和还原版的 DOM、文本、浮层、请求序列、截图逐项比对，结论由机器门槛给出，复核由另一个模型家族做。
4. **如实交付**：做不到的地方写 `// TODO:restore <原因>` 并保留原行为；未覆盖的场景（宿主硬件、长时运行、要造数的页）列清单写明原因。不编造源码，也不编造验证结果。

## 硬规则（所有角色都要遵守）

- **只读原产物**：`legacy-dist/`（或项目配置的产物目录）只读，不改。
- **只访问测试环境**：只访问项目配置里 `recording.allowedHosts` 列出的测试域名，不碰生产，也不访问别的项目的域名。
- **登录由人完成**：人在有界面的浏览器里登录，智能体不输入账号密码，也不调用登录接口。
- **密钥与个人信息**：密钥只从环境变量读，不进仓库、日志、评论，也不从旧前端包里提取。HAR、登录态、接口数据只放在本机状态目录。提交前跑 `scan-secrets`。
- **不准为通过而改规则**：不得修改门槛脚本、比对和归一化规则、阈值或公共库清单来让某一页通过。规则只能走「规则变更单」改，而且只接受等价写法的规范化（见 `references/04-record-regression.md`）。
- **项目隔离**：每个还原项目有自己的配置、状态目录、证据、工单、分支和智能体。不读、不复制其他项目的登录态、HAR、源码和任务状态。
- **作者不自审**：写代码的智能体不合并自己的分支，也不复核自己的产出。

## 先选运行模式

| | 全自治流水线 | 分批轻量模式 |
| --- | --- | --- |
| 适合 | 页数多（约 100 页以上）、多应用，要长时间无人值守 | 页数少（约 30 页以内）、单应用，或目录里已有部分成果 |
| 编排 | 定时运行 `tick.mjs` 派单，角色分工：调度、还原、门槛、录制、修正、裁定、复核 | 一张父单统筹，按阶段建子单：G0 摸底 → G1 引擎接入 → 公共库 → 页面分批 → 规则变更 → 复核 → 收尾 |
| 状态 | Multica 任务元数据 + 本机账本 `$RESTORE_STATE` | 工单回执 + 项目笔记 |
| 合并 | 门槛通过后自动合入 `integration`；集成回归通过后快进到 `main` | 每批一条分支，由收尾单合并，人合 `main` |

拿不准时先用轻量模式。页数超过约 50 页、每批要等录制、或人工推进跟不上时，再升级到全自治流水线。两种模式的工单格式、门槛和录制工具完全相同，只是编排方式不同。

## 工作流总览

```
立项与隔离 → 产物分析 → 引擎接入（配置、清单、工单） → 公共库（入口包、共享组件）
     → 录制基线 ┐
     → 页面还原 ┴→ 门槛 → 合入 integration → 集成回归 → main → 交付
```

入口包、共享组件、页面三条线可以并行开工：公共库先在清单里占好路径（`reserved`），页面一律按清单导入；页面门槛跑的时候，用原编译 chunk 临时顶替还没还原的模块。最后用集成门槛（不顶替）兜底。

## 引擎现状（务必先知道）

引擎目前仍和哈密门户、用户中心的数据放在同一个仓库里（`libingtong/hmrsfw-restore`）。拆仓计划见 `docs/generic/split-plan.md`，还没有执行，所以部分脚本里还写死了项目信息（站点名、接口前缀、多租户 `appCode`、身份切换、SM2/SM4）。新项目接入时：

- 以上游 `main` 的当前提交为准，记下指纹。不要用本机留的旧快照，也不要从另一个下游项目二次拷贝引擎。
- 只拷 `tools/`、`schema/`、`rules/`、`package.json` 和通用文档。不拷 `legacy-dist/`、`queue/`、`registry/`、`out/`、`receipts/`、`tests/interact/`，这些是哈密的数据。
- 写死的项目信息按 `docs/generic/split-plan.md` 末尾的清单逐项改成读配置，或放进项目钩子。每一处改动都记在项目笔记里。
- 引擎有通用价值的修复，另开 PR 回馈给上游，别只留在下游副本里。

配置契约见 `docs/generic/config-schema.md`，任务元数据契约见 `docs/generic/ticket-metadata.md`。各脚本的细节以仓库里的 `docs/pipeline.md`、`docs/gate.md`、`docs/scheduler.md`、`docs/work-orders.md` 为准；本 skill 和它们冲突时，以仓库文档和日期最新的实测为准。
